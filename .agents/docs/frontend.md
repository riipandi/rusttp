# Frontend rules

updated: 2026-11-25T12:45:00+07:00

Contracts and traps for `packages/`: `webapp`, `uilibs`, `e2e`, `emails`, `plugins`. Cross-area rules are in `rules.md`; the reasoning is in `architecture.md`; commands are in `shape.md`. Component catalog: `packages/uilibs/.storybook/stories/components.mdx` (read it before building any UI), with one `<name>.mdx` page per component. StyleX: `stylex-authoring.md` (writing styles), `stylex-installation.md` (the compiler pipeline).

## Layout

- **`plugins`**: Vite plugins shared across packages, imported as `plugins/<name>` (`workspace:*`): `rust-server.ts` (builds and runs the Rust server in dev), `vixum.ts` (the Vite side of the server-rendered document and the route table), `stylex.ts` (the StyleX compiler, used by `uilibs` and `webapp`; `webapp` also passes it to `vixum`'s `plugins`, because the route reader loads route modules and StyleX throws uncompiled).
- **`webapp`**: React SPA, built with the React Compiler; `#/*` is `app/*`. TanStack Router file routes in `app/routes/` (generated, gitignored `app/routes.gen.ts`; `tsr.config.json`, `autoCodeSplitting` on), TanStack Query, TanStack Store (`app/libraries/*.store.ts`), Paraglide (`app/locales/`, `project.inlang/`, generated `app/paraglide/`), Formisch with Valibot (`app/schemas/`), fixtures in `app/fixtures/`. Styles: `app/styles/layout.stylex.ts` (the page shell), `app/styles/pages/<page>.stylex.ts`, `app/styles/element/<name>.stylex.ts`, `app/styles/constants.stylex.ts` (`breakpoints`, `motion.reduce`, `layoutSize`). TanStack devtools in `app/routes/-devtools.tsx` (Shift+D, stripped from production). No `index.html`: the build input is `app/main.tsx` and the output is `apps/server/frontend/` (assets, `.vite/manifest.json`, `routes.json`), embedded by the release server. `public/` holds the favicon set (`favicon.svg` follows `prefers-color-scheme`; `favicon.ico`/`favicon.png` are light-only) and `manifest.json`. `routes/__root.tsx` wraps the app in `UIProvider` and `ThemeProvider`; `uilibs/assets/globals.css` is the only global CSS. `build` and `typecheck` run `tsr generate`, then `tsrs --noEmit --fast` (the Rust port of the TypeScript 7 checker; the workspace has no `typescript` package).
- **Webapp layouts**: `/` (`routes/index.tsx`, landing); `(auth)` (`routes/(auth)/route.tsx`: brand panel plus form column; login, signup, forgot/reset password, verify email, email verified, two-factor, device; placeholders without a backend); `(app)` (customer: `AnnouncementBar` while `adminProfile.role` is `Administrator`, top navigation, `/dashboard`, `/notifications`); `admin` (`/admin`: `-sidebar.tsx` or `-topbar.tsx` by `useCompact()`, the demo-mode `AnnouncementBar` pinned at the top of the content column (`styles.banner`: `top: 0`, or under the 56px top bar below the compact breakpoint; the settings aside is sticky at its 40px height, so a message that wraps beside the sidebar would overlap the aside), the customer layout's bar scrolls away, settings at `/admin/settings` with groups in `settings/-nav.ts`, command bar and shortcuts panel in `-commandbar.tsx`). A `-` prefix keeps a file out of the route tree; group-shared parts sit at the group level (`(app)/-header.tsx`, `(app)/-user-menu.tsx`, `admin/-user-menu.tsx`, `admin/-nav.ts`); `components/nav-sheet.tsx` (`NavSheet`) is the small-screen drawer both layouts share. A route that outgrows a file becomes a folder (`routes/(app)/dashboard/index.tsx` with `-summary.tsx`, `-loans-table.tsx`, `-types.ts`). Shared components: `skip-link.tsx`, `page-title.tsx` (`PageTitle`, the `h1` over `uilibs` `Text` `featured-2`), `message-slot.tsx`, `logo.tsx`, `announcement-bar.tsx`, `shortcut.tsx`, `form-fields.tsx`; the auth pages add `SocialButtons` and `StatusIcon`. `routes/-boundaries.tsx` holds the not-found and error pages, each wrapped in its own `ThemeProvider` (the root's error component replaces the root and its providers).
- **Admin sidebar**: collapses to an icon rail (`admin-sidebar` in `localStorage`, `libraries/sidebar.store.ts`); only the width animates and icons stay on one column; the rail's logo is the face of the one `Toggle sidebar` button; the logo is never a link. The bell (`components/notifications.tsx`, `NotificationsPopover`) is one element that moves between the expanded and rail spots, so an open popover survives a toggle.
- **Command bar**: its entries are derived from `admin/-nav.ts`, `settings/-nav.ts` (as `Settings → Page`), and `admin/-user-menu.tsx` (`accountItems(m)`, `appItems(m)`, `themes(m)`), plus Notifications by hand; a page added to those files is searchable at once (a page's own name wins: a settings group's name is not its keyword). The cheat sheet focuses its panel (`initialFocus`), and closing it does not return focus to the trigger (`finalFocus={false}`).
- **`uilibs`**: source-sharing React library (StyleX, Base UI); consumers import `uilibs/<path>` from `src/` and compile it. `src/base/`, `src/extra/` (compositions, kanban and sortable included; plan-00011 wave 5 added `link/`, `stack/`, `container/`, `hidden/`, `image/`, `carousel/`, and `step-dots/`, and `BadgeAnchor` lives in `badge/`), `src/data-grid/` (imported as `uilibs/data-grid`), `src/charts/` (`charts.mdx` is its docs page; the recipes and `chart.samples.tsx` live in `charts/stories/`), `src/icons/`, `src/styles/`, `src/theme/` (`ThemeScope`, `usePortalContainer`, `ThemeSwitcher`), `src/hooks/` (`use-media-query`, `use-responsive-value`), `src/assets/` (reset, fonts, `globals.css`), `src/contracts/` (story-only cross-component checks). The data grid is split: `data-grid.tsx` (provider, root), `data-grid-cell.tsx` over `data-grid-cell-ops.ts` and `data-grid-cell-editor.tsx`, `data-grid-table.tsx` over `-head`, `-body`, `-utils`. The sidebar order is `storySort.order` in `.storybook/preview.tsx` (Introduction, Base Components, Extra Components, Data Grid, Visualizations, Contracts); a new top-level title is added there and, to start collapsed, to `sidebar.collapsedRoots` in `.storybook/manager.ts` (slugged ids; only Base Components starts open; the addon panel starts hidden through `showPanel: false`; the manager bundle needs a Storybook restart). Cross-component checks are `Contracts/*` stories. Storybook binds `localhost` only: `core.allowedHosts` in `.storybook/main.ts` is a list, never `true` (any website could then read sources and write files through its WebSocket and MCP server).
- **`e2e`**: Playwright (`playwright.config.ts`; projects Chromium, Firefox, Mobile Safari, Safari). Screen objects `screens/<area>/*.screen.ts` with specs beside them, registered in `fixtures/test.ts`; `utils/routes.ts` (`allRoutes`); `utils/axe.ts`; the sweep `screens/a11y/a11y.spec.ts`. Without `E2E_BASE_URL` it builds the SPA and starts the server on `127.0.0.1:3000`; reports go to `.output/`.
- **`emails`**: jsx-email templates, inline `style` props, no Tailwind. `templates/<name>.tsx` exports `templateName`, `previewProps` (sample data), `templateProps` (`{{snake_case}}` placeholders without inner spaces), and `Template`; shared parts in `components/` (`when.tsx` turns an empty-able placeholder into `{% if %}`; `rich-content.tsx` inserts `{{content_html|safe}}`). Dark mode targets `data-dm` attributes because the inline plugin strips classes and `<style>`. `pnpm --filter emails dev` (`node preview.ts`) previews on `:3030`; `build` (`node build.ts`) writes `apps/server/emails/<name>.html` and `.txt` (gitignored); `check <file>` runs the client-compatibility check; `jsx-email.config.mjs` minifies when `NODE_ENV=production`.

## UI library

- A component is `<name>/{<name>.component.tsx, <name>.stylex.ts, <name>.stories.tsx, <name>.mdx, index.ts}` under `src/base` (Base UI wrappers) or `src/extra` (compositions); `index.ts` re-exports the component file and, by name, only a recipe a consumer composes (`buttonSquare`, `calendarStyles`); a `*.stylex` file is never `export *`ed, so a recipe stays private until a consumer needs it, and a sibling component that needs one imports it by its file path. `<name>.mdx` is the props page (below). The data grid sits apart in `src/data-grid/` (its own top-level folder, like `src/charts/`) and has no single stories file (its `Playground` is `stories/data-grid-playground.stories.tsx`, titled `Data Grid/Playground`, with flat story-only args folded into `tableLayout`; the seven topic files have none, and neither do the `contracts/` stories); its page, `data-grid.mdx`, attaches to `stories/data-grid-basics.stories`.
- Style values come from `src/styles/` (`colors`, `tokens`, `popup`, `utils`); a literal color, size, or duration is a defect. Dark mode is `data-theme` plus the overrides in `styles/themes.ts`, never a per-component media query. A condition (pseudo-class, `@media`) nests in the value it changes. The focus ring is `focusRing.root` from `styles/utils.stylex`, composed first; hidden-but-read text is `visuallyHidden`. Design tokens (`colors`, `tokens`, `themes`) change only on the owner's decision.
- The caller's `style` merges last in `stylex.props(...)`; no `className`, no raw `style` beside a `stylex.props` spread.
- Inside the package use `#/*` or a relative path; across packages `uilibs/<path>`. `src/*` stays importable without the Storybook config.
- A wrapper is typed with `React.ComponentProps<…>` so `ref` is a prop; no `ComponentPropsWithoutRef`, no `forwardRef`.
- Names and roles (plan-00011 wave 3): a name that depends on its item is a function in `labels` (`InputPhone` `selectCountry(countryName)`, Sortable `handle(itemName)`, Kanban `columnHandle(columnName)`); a toggle keeps one name and reports state with `aria-pressed` (`InputPassword` `labels.toggle`). A scroll wrapper is `role='region'` with `tabIndex={0}` only while it overflows (`Table`, measured with a `ResizeObserver`), never statically; the Kanban board is a region named by `labels.board` with no tab stop. `ItemGroup` puts `listitem` on a wrapper `div` through `useRender`, so a rendered link keeps `role='link'`. `Alert` has no role unless `announce` opts into `role='status'`. `LoaderText` is one `role='status'` region that hides the inactive text. A chart is a Tab stop only when it has a `tooltip` (it draws the focus ring on its host), and `ChartContainer` `description` becomes the svg `<desc>`.
- Data grid accessibility (plan-00012, plan-00013): every part that renders a `<table>` (`DataGridTable`, `Virtual`, `Dnd`, `DndRows`, `Header`, `Base`) requires `aria-label` or `aria-labelledby` by type (`DataGridTableName`; a name belongs to one grid, so it is a prop and never a `labels` entry). A row control is named after its row: `getRowLabel(row)` on `DataGrid`, else `labels.rowNumber(position)`; `selectRow`, `pinRow`, `unpinRow`, `expandRow`, `collapseRow`, and `dragToReorderRow` are functions of that name and a column's grip is `dragToReorderColumn(title)`. Drags speak through `dragAccessibility` from `extra/sortable/drag-announcements.ts` (`DataGridLabels` extends `DragLabels`). Loading is `aria-busy` on the table plus one live region in `DataGridProvider` (`labels.loading`, then `labels.loaded(count)`), and the spinner inside the loading row is `aria-hidden` so it does not speak twice. The page buttons are a `nav` named `labels.pagination`. With `onRowClick`, rows are one Tab stop kept in a store on the context (`data-grid-row-stops.ts`: the last row focused, else the first rendered one, so a virtualized grid always has one), ArrowUp, ArrowDown, Home, End, PageUp, and PageDown (a page is `getDataGridPageRowCount`, shared with the cell grid) move between rows, Enter or Space on the row itself calls `onRowClick` (a control inside keeps its keys), and in a `cellSelection` grid the grid stays the one stop and Enter on a cell calls it. Each resizable column's edge is a focusable `role='separator'` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax` (`Number.MAX_SAFE_INTEGER` for a column with no `maxSize`, because ARIA 1.2 reads a missing maximum as 100), `aria-valuetext` from `labels.columnWidth(width)`, `aria-controls` naming its header cell (`getDataGridHeaderDomId`), and `labels.resizeColumn(title)`: arrows 10 px, Shift 50 px, Home and End to the limits, Enter resets (the window splitter collapses here; a collapsed column is a sliver); its direction follows the drag, and both follow the computed `direction` of the handle through `isColumnResizeMirrored`, mirrored for an end-pinned column (the `columnResizeDirection` table option is not read), and the step is the pure `nextColumnSize`. Focus is always drawn: a cell-selection grid that holds focus with no active cell (first Tab, or after Escape) draws the 2 px library ring on the table (`gridFocusable`, `:focus-visible:not([aria-activedescendant])`), and once a cell is active the cell's 1 px edge is the indicator and the table draws nothing (the `Focus` story). The keys are proved by the `Row click` and `Column resizing, keyboard` stories (including the `from dir` case) and listed in `data-grid.mdx`.
- Buttons: `size` is a size only (`xsmall | small | medium | large`); a Button with no children is the icon-only square, and a Button with custom children (an avatar trigger, a notification bell, a page number, a grip) takes `buttonSquare[size]` to be square. `ButtonGroup` passes position, fill, and the default `size` and `variant` through `ButtonGroupContext` (in `base/button/`, because `base` may not import `extra`); Button, Input, and Select read it, and nothing clones children. `ButtonGroupContext`, `useButtonGroup`, and `buttonGroupMember` are not exported from `base/button`: the four library parts that join a group import them from `button-group.context`, and no consumer builds a group member of its own (export them when one does). `buttonAppearance(variant, color)` is the Button look for an element that is not a Button (Calendar's month arrows). `InputGroupButton` takes `xsmall | small`. `InputPassword` `showIcon` and `hideIcon` are `Glyph`s. `LinkButton` is gone (plan-00011 phase 38): a Button takes `render={<a />}` (or a router link) and draws the real `<a>` through `useRender`, so it keeps the `link` role with no override; `render` is for links only (no `disabled`, no `type`), a loading Button ignores it, and a link that looks like a button passes its text as children so it is not read as icon-only. A text link inside a sentence is `Link` (`extra/link`).
- Props that name the same thing are named alike (plan-00011 wave 4): the current page or item is `current` (Pagination), a media or shape slot is `kind` (not `variant`: FieldLegend, ItemMedia, EmptyMedia; `variant` stays the Button and Badge fill), a part a trigger shows or hides is `show<Part>` (`ComboboxTrigger` `showIcon`), built-in strings are `labels` and never `i18n` (the data grid's `labels` is `Partial<DataGridLabels>`), and a Popover `elevation` is the `shadow` token it draws (`outline | raised | overlay`, default `raised`). A static surface (Card, Alert, Kbd, Empty, Label, Skeleton) takes `render` through `useRender` and `mergeProps`; `mergeProps` needs an `as React.ComponentPropsWithRef<'div'>` cast on the first object when it carries `data-*` keys, and `ref` goes through `useRender`'s `ref` parameter.
- New components (plan-00011 wave 5): `Link`, `Stack`, `Container`, `Hidden`, `Image`, `BadgeAnchor`, `Carousel`, and `StepDots` take `style` and no `className`; the static ones take `render` through `useRender`. `Stack`, `Hidden`, and `Text` take responsive `{ small, medium, large, xlarge }` values, compiled to static media styles; `useResponsiveValue` is the JavaScript twin and follows the viewport, not the container. A responsive set keys the whole style on the media query (`{ [breakpoints.medium]: { flexDirection: 'row' } }`); a media nested inside a property erases the base value because `stylex.props` keeps only the last. The breakpoint values live in `styles/tokens.stylex.ts` and are mirrored in `text.stylex.ts`, `stack.stylex.ts`, `hidden.stylex.ts` (a media const used as a `create` key resolves only from its own file) and, as numbers, in `hooks/use-media-query.ts`; each stylesheet mirror has a unit test that compares it with the tokens, so a changed breakpoint is edited in the tokens and every mirror. A new Base UI portal component passes `container={usePortalContainer()}` (`theme/theme-scope.context.ts`) so its popup follows a `ThemeScope`; outside a scope it is `undefined` and Base UI behaves as before. A scroll strip that takes the keyboard (`Carousel`) is a `role='group'` with `tabIndex={0}` and an inline `no-noninteractive-tabindex` disable that names the axe rule (`scrollable-region-focusable`); a control that disables at the end of a range (Carousel Previous and Next) keeps `focusableWhenDisabled` so focus does not drop. A mark or dot that is not the active one draws `borderControl`, never `backgroundTrack` (about 1.1:1 on a white page, under WCAG 1.4.11's 3:1). A consumer `style` that overrides a component's padding sets the longhands (`paddingBlock`, `paddingInline`), because a `padding` shorthand loses to the component's longhand.
- Size names are spelled out everywhere (`xsmall`, `small`, `medium`, `large`, `xlarge`, `xxlarge`): props, recipe keys, `glyphSize`, `markSize`, and `Text`'s responsive keys (`stylex-authoring.md`, "Controls"); an abbreviation (`sm`, `md`) is a defect.
- A form control takes `size` (`small`, `medium`, `large`) and composes `controlSizes[size]` after `controlBase.root` (text entry; `controlBase.within` for a wrapper holding the real input) or `controlPress.root` (press target) from `styles/control.stylex.ts`, then its own style, then the caller's. A Field control renders through Base UI's `Field.Control` (or is a Base UI control), so `aria-invalid`, `data-invalid`, label and description wiring come from the Field. Text controls fill their container; a fixed width comes from `style`.
- Control edges use `borderControl`; `borderNeutralFaded` is for dividers and cards. The 3:1 edge applies to the `outline` variant of a text-entry control (the default); `faded`, `ghost`, and `headless` draw no edge at rest, keep the focus ring and the critical edge when invalid, and need a visible label (plan-00008 D11). Text pairs clear 4.5:1 and control edges 3:1 in both themes; `borderControl` keeps 3:1 on the page, `backgroundNeutral`, and its hover surface (light 4.28, 3.59, 3.30; dark 5.77, 3.77, 3.22; measured 2026-11-22). A chart series takes a `foreground*` token (5.6:1 or better), never a `background*` fill (warning 1.86:1, neutral 1.30:1 in light); a series that carries meaning needs 3:1 or a label. Chart marks may take a theme token (`var()` resolves in SVG attributes).
- Every string a component renders or names is one `labels?: Partial<XLabels>` prop with English defaults (`{ ...defaultLabels, ...labels }`); never `text`, `label`, `title`, `showAriaLabel`, or `removeLabel`. There is no locale context. Kanban and Sortable put the drag announcements (`pickedUp`, `movedOver`, `dropped`, `cancelled`, `instructions`) in the same object, and a drag names its item by `aria-label` or text, never by id (`sortable/drag-announcements.ts`).
- Color and fill are two props, as in Reshaped: `color` is the role and `variant` is the fill. Alert, Toast (`neutral | primary | positive | warning | critical`), Badge (the same, default `primary` for `solid`), Button (`primary | neutral | critical | positive | warning`, plus `media`, white on a photo or dark surface, and `inherit`, the parent's text color), Tooltip (`neutral | inverted | dark`), and menu items (`neutral | critical | primary`) take `color`; Button and Badge take `variant` `solid | faded | outline | ghost` (default `solid`), and every fill has every color. `critical` marks a destructive or irreversible action; there is no `tone` and no `destructive` variant. An icon-only control or an empty table header carries `visuallyHidden` text or an `aria-label`. Glyphs are `@keyline-icons/react`. `base` never imports from `extra`, except Button's `Spinner`.
- Checkbox, Switch, and Radio render as `span`/`div`, so `:disabled` never matches: disabled, focus, and cursor come from `controlPress.root` (`[data-disabled]`). A story claiming a disabled look asserts computed `opacity` and `cursor`.
- A scroll container is a named, focusable region (`Table`'s wrapper: `role='region'`, `tabIndex=0`, `labels.region`); a control that must fit a phone shrinks instead of overflowing. Under `forced-colors: active` a state drawn with a background or shadow gets an outline or system color; under `prefers-reduced-motion` motion is off, or slowed for a spinner.
- The a11y gate: `pnpm --filter uilibs test` runs every story twice, in the `storybook` (light) and `storybook-dark` projects (the browser context's `colorScheme` decides which theme the `system` global resolves to), runs axe on each, and fails on a violation. A story that logs a `console.error` (a duplicate key, an invalid style property) also fails; `parameters: { consoleErrors: 'off' }` opts out and must name the audit finding. A third project, `unit`, runs `src/**/*.test.{ts,tsx}` in Chromium (the logic no story exercises: theme storage, drag announcements, and `styles/contrast.test.ts`, which converts the OKLCH tokens to sRGB and asserts the contrast pairs; a known token failure is an `it.fails` that its fixing phase flips). A story that proves an open defect carries `tags: ['!test']` and names its finding; the fix removes the tag. `STORYBOOK_TEST_BROWSER=firefox|webkit` runs the story projects in another engine; the nightly CI job does both, and under `webkit` `vite.config.ts` skips stories tagged `skip-webkit` (the Menubar `Playground`, F-12: Base UI's focus guards are `role=button` spans there). `.github/workflows/uilibs.yml` runs typecheck, `pnpm --filter uilibs test`, and `storybook:build` in Chromium on every push or pull request that touches `packages/uilibs/**`, `pnpm-lock.yaml`, or the workflow. Under test, the preview's `beforeEach` settles the page before each story renders: it waits until the StyleX dev stylesheet in the page equals `/virtual:stylex.css` (the runtime fetches it only after the server's 150 ms poll sees new rules, so a play could measure an unstyled page) and until the web fonts have loaded (`swap` re-measures text); a play never needs a `waitFor` around a computed-style or box read to cover either. axe runs after `play`, so a popup is checked only by a story that leaves it open: every overlay (dialog, alert dialog, drawer, sheet, popover, preview card, tooltip, toast, the three menus, navigation menu, select, combobox, autocomplete, command dialog) has an `Open` story (page convention, below). The only allowlisted element is Base UI's focus guard (`[data-base-ui-focus-guard]`, `.storybook/preview.tsx`); `STORYBOOK_A11Y_GATE=todo` or `off` relaxes it for a local run only. MDX docs pages are wrapped by `.storybook/docs-container.tsx`.
- Stories are grouped by prop axis: `Playground` (the only story with controls: `.storybook/preview.tsx` turns them off, and the `Playground` sets `parameters: { controls: { disable: false, include: [...] } }` naming exactly the controls it offers; its `argTypes` and `args` sit on the story, never the meta; every option list comes from the component's stylex map keys or union type; the `render` reads the args and routes a compound component's part props, such as `DialogContent` `size`, to that part; a `play`, when there is one, asserts only what holds under the default args), then one story per axis the component has (`Variants`, `Colors`, `Sizes`, `States`, `Orientations`, `Sides`), then behavior stories (`Keyboard`, `Controlled`, `OnClick`) apart. An axis story draws its values with `Axis` from `src/contracts/story-axes.tsx` (a labelled, wrapping list; cells carry `data-<axis>`) and its `play` asserts them: `Variants` that each value renders and differs from the default, `Sizes` the heights (`expectControlHeights`), `States` each state (the disabled tokens and cursor for disabled, `data-invalid`, `aria-busy`). The canvas is fluid (`layout: 'padded'` in `.storybook/preview.tsx`): a story sets no `minWidth` and no `layout: 'centered'`, so the 390 px layout shows. `Axis` takes a second axis (`columns`, `columnAxis`), `fill` (cells that fill their row, for text-entry controls) and `wide` (a chart or list that uses the canvas width). Story helpers live in `src/contracts/control-sizes.tsx`: `cellOf` (a cell by `data-<axis>`), `expectControlHeights`, `expectBoxSizes`, `expectDisabledLook` (no opacity, the disabled tokens, and the cursor unless `cursor: false`), `expectDockedTo` (a sheet or drawer flush against its edge), `backdropOf` (the backdrop of a dialog or sheet; a focus guard sits between it and the popup, so it is not the popup's previous sibling). A menu row that is disabled dims but keeps the default cursor, so its `play` passes `cursor: false`. A floating popup flips when the canvas leaves it no room, so a `Sides` story asserts that each popup opens, not which side. Several calendars on one canvas each need their own `labels.labelNav` or axe fails `landmark-unique`; a story that draws several resizable groups sets `parameters: { canvas: 'auto' }` to size its own cells. `contracts/control-sizes.stories.tsx` stays the cross-component height contract. In the Storybook UI a `play` does not run on load: the Interactions toolbar global (`interactions`, default `off`, in `.storybook/preview.tsx`) turns it on, and the project `beforeEach` sets the current render's `renderOptions.autoplay` from it, because Storybook 10.6.8 has no option for this. Rerun and the step buttons in the Interactions panel emit `FORCE_REMOUNT`, which reuses the same render, so `preview.tsx` records that story id and plays it once whatever the global. The test run (Vitest browser mode) always plays.
- Every component folder has a docs page, `<name>.mdx`, in one shape: `import { Canvas, Meta } from '@storybook/addon-docs/blocks'`, `import * as Stories from './<name>.stories'`, `<Meta of={Stories} />`, then `# Name` with one sentence (and when to pick it over a look-alike), `## Import` (a `jsx` block, then one line naming what it is built on, linking the Base UI part it wraps), `## Anatomy` (a bullet per part, then the part tree as a `jsx` block with no import and no leading `;`), `## Examples` (two to four `<Canvas of={Stories.X} />` blocks, each with at most one sentence), `## Accessibility` (when the component takes focus or keys, or has a naming rule; the shape is below), `## API reference` (one sentence for the shared `style`, then a `###` per part with a props table, a data attributes table, and a CSS variables table where the part has them), and `## Caveats` only when there are real ones. A props table has two columns, `Prop | Description`, and a cell is the values in code, `<br />`, one sentence, and `Default \`x\`.`; it lists only the props this library adds or narrows. Data attributes come from Base UI's own list plus the ones this library sets (`data-slot`, `data-selected`, and so on). Usage examples live in the stories and show through `Canvas`; the pages carry no other example. The name is `<name>.mdx`, not `<name>.stories.mdx`, which Storybook 10 cannot index (addon-docs excludes it, `preset.js:865`); `.storybook/main.ts` globs `../src/**/*.mdx`, and `.storybook/docs-container.tsx` lets a table scroll inside the page at 390 px. Docs entries are not tests: the gate count does not move. react-docgen's `<ArgTypes>` is not used because it lists every inherited Base UI and DOM prop.
- **Accessibility, usage source, `Open`, `Keyboard` (the docs page convention, plan-00011 phase 47; copy `src/base/dialog/dialog.mdx` and `dialog.stories.tsx`).**
  - **`## Accessibility`** sits after `## Examples`. It opens with one or two sentences: the role, what names it, and what the story proof is (the `Keyboard` and `Open` stories are named, not embedded). Then a `Key | Action` table with one row per key the component answers (`Enter` or `Space`, `Tab` and `Shift + Tab`, the arrows, `Home` and `End`, `Escape`, typeahead), then bullets for the naming rule (what needs an `aria-label` or `labels`), where focus lands and returns, and one link to the component's Base UI page for the rest. Never copy Base UI's key list; list what this library's page adds or what its stories prove. A claim on the page is proved by a story, never by memory: a key row has a line in the `Keyboard` play, a naming rule has an axe-checked story. A component with no keys and no naming rule (a Separator that is decorative, a Skeleton) puts its one-line note in `## Caveats` instead and has no `## Accessibility`.
  - **`docs.source.code`.** Every story a page embeds with `Canvas` sets `parameters.docs.source.code` to a short consumer snippet (the parts with the props that story shows, sample strings kept, `…` for filler). Without it "Show code" prints the story's CSF object: the `Axis` harness, the `play` function, and the test helpers (checked on the built Dialog, Button, and Table pages). A story that is not embedded needs none. The snippet is plain JSX with no `import` (the page's `## Import` block has it) and uses no harness, `Axis`, or `styles.` helper that a consumer cannot copy; where the story passes a StyleX object, write `style={…}`.
  - **`Open` story.** Every overlay has a story named `Open` that renders the popup open at rest (Base UI `defaultOpen` on the root) and whose `play` only waits until the popup is visible and asserts its name and description. It is not embedded in the page. axe runs after `play`, so this is the only story that checks the popup's own markup; the pilot was mutation-checked (an unnamed button inside the popup fails `Open` with `button-name`). The dialog `Open` story reuses the same content function as its `Keyboard` story.
  - **`Keyboard` story.** A component with keys has one story named `Keyboard` that drives the table with `userEvent` and asserts focus, state, and the popup's presence for each key row. Press keys through `pressUntil` from `src/contracts/keyboard.ts`: WebKit (and a loaded runner) loses a key sent while a popup settles, so the key repeats inside `waitFor` until its result shows. An idempotent key (`Escape`, `Home`, `End`) passes only the settled check; a key that moves state (`ArrowDown`, `Tab`, and `Enter` on a trigger that may already be open) passes `when`, a precondition checked before each press, so it is sent only while the state has not moved. A menu or listbox opens with nothing highlighted on some engines: press `Home` first (as the Select `Keyboard` story does) so an arrow's step is the same everywhere. Past a popup's last control, Tab lands on Base UI's focus guard before it hands focus back, so read focus inside `waitFor`. Do not use fixed sleeps. The play asserts the behavior on the page; a key the component does not own (Base UI's) is a row on the page only if the play presses it.
  - **Keyboard plays, lessons from the wave 7 pages.** Guard a state-moving key on the control that takes it, or on `aria-expanded`, never on the popup being in the DOM: a closing popup stays in the page for its exit animation. Close by `Enter` is one press and a `waitFor` with a 10 s timeout, never `pressUntil`. Re-query popup controls after each reopen, because the popup remounts. In WebKit, Escape through `userEvent` on a `CommandDialog` whose input holds text logs React `act` errors (Base UI blurs the input while the dialog closes, inside Storybook's `act` wrapper); the Command `Keyboard` play sends that one Escape as a native `KeyboardEvent` inside `waitFor` instead (issue-00008, archived). `pressUntil` with `when` suits arrow and Tab moves in composite widgets (Tabs, ToggleGroup, Toolbar). A synthetic key does not scroll natively, so a scroll-by-arrow claim cannot be proved by a play. An attribute set asynchronously (`aria-activedescendant`) needs `waitFor`. Hoist helpers such as `lifted` and `live` to module scope (`consistent-function-scoping` flags them inside a `play`). A control-only prop that a story only seeds (`defaultVisible`, `defaultOpen`) needs a `key` on the component so a changed control remounts it.
  - **Page conventions that came out of it.** A component with a naming rule but no keys (Avatar, Meter, Progress) has `## Accessibility` with a lead and bullets and no `Key | Action` table; only a page with proven keys gets the table, and each row maps to a play line. An overlay with no default-open prop (Toast) has an `Open` story that raises the item with `timeout: 0` and leaves it up. A page may embed stories of another folder (`import * as X from '../../icons/icons.stories'`). An existing `parameters` object is merged with `docs.source.code`, never duplicated. The Base UI behaviors the pages record (Switch flips on Enter and Space, Toolbar ignores Home and End, Tabs select on Enter or Space and the arrows only move focus, NumberField steppers are `tabindex=-1` and Shift+Arrow steps by 10, RadioGroup arrows move focus and select and wrap, Drawer focuses the popup itself, a closed Combobox clears on Escape, Tooltip sets no accessible description) are proved by a play, so a Base UI upgrade that changes one fails a story.
  - **Playground controls.** `include` names every scalar prop (boolean, number, string, a list of values) and every glyph prop the page documents for a part the Playground renders; callbacks, `labels`, `style`, `render`, `id`, `name`, and the chart Playgrounds (plan-00010 D7) are exempt.   - **Overflow gate.** Under test, the preview's `afterEach` fails a story whose page is wider than the viewport, and every story renders at 390 px (`initialGlobals.viewport = { value: 'phone', isRotated: false }`, set only under test so the Storybook UI canvas stays fluid; the Storybook Vitest addon sets the window itself from `globals.viewport.value` and ignores `browser.viewport` in `vite.config.ts`; the global is an object, because a bare string leaves the window at 1200 px and the gate would pass without measuring, so the preview's `afterEach` also fails a story whose `window.innerWidth` is not the width its viewport global names). The test canvas has no `padded` padding, so a story is flush with the page edge. The gate found a Switch hit area that overhung its track, a `visuallyHidden` box whose negative end margin pushed the page sideways in RTL, and popups as wide as a full-width trigger.

## Webapp forms

Formisch (`@formisch/react`) with Valibot; the auth pages are the reference.

- The schema in `app/schemas/<domain>.schema.ts` is the only home of a rule: types, messages, cross-field checks (`v.forward(v.partialCheck(…), ['confirm'])`). Field components and routes never validate; Base UI `Field`'s `validate` and `validationMode` stay unused.
- One schema file per domain (`auth`, `identity`, `loans`, `notifications`). A schema is `<name>Schema`; what a form sends is `<Name>Request` and an API body `<Name>Response`, both `v.InferOutput`. A shared rule is exported from its domain file (`emailSchema`, `newPasswordSchema`, `captchaSchema`, `tokenSchema`). A route declares no types file.
- A route calls `useForm({ schema, initialInput })` and submits with `handleSubmit(form, onValid)` on a `uilibs` `<Form noValidate>`: `onSubmit={(event) => { event.preventDefault(); void submit() }}` (the one-argument overload returns a function without an event). An email field uses `inputMode`, not `type='email'`, so native validity does not block Valibot.
- Field components in `app/components/form-fields.tsx` take `field: FieldLike<T>` beside their own props, wrap the control in the `uilibs` `Field` with `invalid={field.errors !== null}`, and show `field.errors[0]` through `FieldError`. `input` is `T | undefined`: read `field.input ?? ''` or `?? false`.
- A native input spreads `field.props` (`name`, `ref`, `autoFocus`, `onFocus`, `onChange`, `onBlur`). A composite control wires them by hand: Checkbox `inputRef={field.props.ref}`, `checked`, `onCheckedChange={field.onChange}`; OTP `value`, `onValueChange`, and `field.props.ref` on its first slot. `CodeField` takes digits unless `characters='alphanumeric'`; `uppercase` capitalizes; `focusFirst` autofocuses (the one `jsx-a11y/no-autofocus` exception, for two-factor and device).
- A link carrying a token (`/reset-password?token=`, `/device?token=`) validates it with `validateSearch` and a Valibot schema; otherwise the route's `errorComponent` renders an invalid-link page.
- `field.props.name` is the JSON of the path (`["password"]`): never an `id` or `htmlFor` (use `React.useId()`); tests find a field by its label.
- Base UI's `Form` focuses the first invalid control on a failed submit; the refs stay because Formisch's `focus()` and `shouldFocus` need them.

## Webapp state

TanStack Store, one `libraries/<name>.store.ts` per concern (`sidebar`, `commandbar`, `notifications`, `locale`). State one component owns stays in `useState`; a store is for state that distant components share or that persists.

- A `*.store.ts` imports `@tanstack/store` only, never React. State is immutable; `setState` returns the same reference when nothing changed. Actions are arrow properties in `createStore(initial, ({ setState, get }) => ({ … }))` (a method shorthand trips `unbound-method`).
- A computed value is a derived store, `createStore(() => …)` (`sidebarCollapsed`, `unreadCount`).
- Components read with `useSelector(store, selector)` and select the smallest slice (`useSelector(unreadCount, (count) => count > 0)`), and call `store.actions.x` to write without subscribing; a selector returning a new object needs `{ compare: shallow }`. Writes to several stores go in `batch()` (`resetAdminUi` in `routes/admin/route.tsx`).
- A module-level store outlives its route: the owning layout resets visit-only state on unmount.
- Preferences live in `localStorage`, read once at store creation (the SPA renders on the client only). One key per preference: `theme` (`uilibs/theme`), `admin-sidebar` (`collapsed`/`expanded`; anything else reads as expanded), `admin-hotkeys` (only bindings that differ, keyed by id), `locale`. Under `/admin/settings` the sidebar shows as the rail for the visit and writes nothing (`useFoldSidebarOnSettings`).
- A storage read or write that throws falls back to the default; toggles still work for the session. No stored shape is migrated.
- E2E seeds a preference with `page.addInitScript` before the app reads it (`admin.screen.ts` `storeCollapse`), never by reloading after `setItem`.
- Notifications come only from `notificationsStore` and `unreadCount`, seeded from `fixtures/notifications.ts`; an endpoint replaces the source and keeps the actions (`setRead`, `markAllRead`, `dismiss`, `dismissAll`).

## Webapp i18n

- Catalogs are `app/locales/<locale>.json` (flat; `en` base, `id` second), listed in `project.inlang/settings.json`; compiler options in `project.inlang/paraglide.config.ts`. Every key exists in every locale.
- Keys are sorted ascending in code-point order in every locale (`"sort": "asc"` keeps tooling in line). Check: `python3 -c "import json,sys; [print(f, list(d:=json.load(open(f)))==sorted(d)) for f in sys.argv[1:]]" packages/webapp/app/locales/*.json`.
- Keys are semantic `snake_case` led by an area (`page_`, `app_`, `admin_`, `auth_`, `notifications_`, `commandbar_`, `shortcuts_`, `validation_`, `boundary_`, `form_`) and are not renamed once used. Values are named (`m.notifications_title_unread({ count })`). A sentence is one message with a placeholder where an element goes (`slotMarker('link')`, rendered by `components/message-slot.tsx`), never cut around a link.
- A component gets messages from `const m = useMessages()` (`libraries/messages.ts`), which subscribes to the locale store; a route's `staticData.pageTitle` uses `getMessages()`. `.oxlintrc.json` bans importing `#/paraglide/messages` outside `libraries/messages.ts` and `schemas/`. Call messages statically (`paraglide/no-dynamic-message-access`). A finite set of choices is a function of `m` (`summaryLabel(m)`, `groups(m)`).
- Messages are read at render, never at module load; a Valibot rule takes `() => m.validation_…()`. A form that shows errors calls `useRevalidateOnLocale(form)`.
- The language is `libraries/locale.store.ts` (`localeStore`, `localeNames`, `set`): key `locale`, first visit from the browser language, then English; no locale in the URL. A change re-renders in place (popovers, inputs, focus survive) and rewrites `<html lang dir>`; Paraglide's `setLocale()` (a reload) is not used. Pickers: `components/language-menu.tsx`, `components/theme-menu.tsx`, both in the account menus; `components/preferences-menu.tsx` holds both on pages with no account menu.
- API data is not translated: figures arrive as ids and the label is a message; dates are ISO strings and counts numbers (`loanSchema.due`, `notificationSchema.time`, `summaryItemSchema.value`), formatted by `useFormat()` (`libraries/format.ts`: `date`, `relative`, `number` over `Intl`). A pre-formatted string in a schema or fixture is a defect. `uilibs` strings come through `labels` (`CloseButton`, `InputPassword`, `OTPField`); `uilibs` imports no i18n. `ThemeSwitcher` takes `labels` (`toDark`, `toSystem`, `toLight`) but the webapp no longer renders it; `ThemeMenu` is the picker.
- `app/paraglide/` is generated (`pnpm generate`, or the Vite plugin) with `outputStructure: 'message-modules'`, because `plugins/vixum`'s own Vite server has no Paraglide plugin to resolve virtual modules.

## Webapp accessibility

The axe sweep (`packages/e2e/screens/a11y/a11y.spec.ts`) visits every route in `allRoutes` at 390 and 1440px, light and dark, on Chromium, and fails on any violation or horizontal overflow. A new route goes into `allRoutes`.

- A field has a visible `FieldLabel` above its control; the OTP field is named by it (`aria-labelledby`).
- A button's accessible name contains its visible text (WCAG 2.5.3): `HG, account menu`, `Search ⌘ K`; the longer purpose goes in `aria-description`. A state toggle keeps one name and one element, saying the state with `aria-expanded`, so focus is never dropped by a remount.
- Each layout starts with `SkipLink`; a page has one `h1` (`PageTitle`, and on the 404 and error pages); every region is a named landmark.
- A control without a backend calls `notWired('what')` (`libraries/not-wired.ts`, one `console.info`); the change that wires it replaces the call.
- Inline links keep an underline; motion has a `motion.reduce` branch; widths and gutters are `layoutSize`, breakpoints `breakpoints`.
- Page layout is `Stack` (a row or a column with a `gap` step, `render` for the element) and `Container` (`size={layoutSize.page}`, `.reading`, `.form`: the `container` tokens stop at 32rem, so a page width is a CSS length; `layout.gutter` is the inset). A style sheet keeps flex only for one control's own box (the sidebar header, the captcha, a menu label) or where the webapp's own `compact` and `narrow` breakpoints decide the direction (the aside, the shell, the top bar; the direction there follows `useCompact()`, since `Stack` responds at `small`..`xlarge`). Code in the entry chunk must not import `Stack`: it is 6 KB raw and 2 KB gzip and comes along with every chunk that imports it, so `routes/-boundaries.tsx` and the dashboard's `pendingComponent` (the route's page and skeleton) lay out with plain flex and `Container` (`styles/element/boundaries.stylex.ts`). Check `just size` after a layout change.

## Keyboard shortcuts

`@tanstack/react-hotkeys` (beta: read the docs of the catalog version before changing a call). The admin is the pattern.

- Declare every shortcut in `libraries/hotkeys.ts` with `defineAppHotkeys` and `meta: { name, group }`; register it with `useHotkey(useAppHotkeys()['id'], callback)`; never a key string at a call site. Ids are a contract (saved rebindings key on them). The `Register` augmentation types them.
- Bind with `Mod`, never `Meta` or `Control`. A physical `[Code]` binding only where position matters; command letters follow the character. A sequence is an array (`['G', 'O']`); single-key and sequence shortcuts need the rebinding screen.
- An overlay is wrapped in `<HotkeysProvider scope='<name>' exclusive enabled={open}>`; its own hotkeys, including the one that opens it, go in a child.
- Labels are `formatForDisplay` (through `components/shortcut.tsx`): `⌘ K` on macOS, `Ctrl K` elsewhere. A shortcut beside a control sets `aria-keyshortcuts` (`ariaKeyShortcuts()`: `Meta+K` or `Control+K`, since `Mod` is not a key name) and hides its keycaps from assistive technology; `useHotkeyHint` dims them until the modifier is held.
- Rebinding uses `useCustomHotkeys` and `useHotkeyRecorder` with `maxSteps: Infinity`, `detectConflicts: true`, a `validate` asking `findConflicts`, and an `onReject` mapping each `reason` to app wording; `onCustomHotkeysChange` saves.
- E2E waits for the layout (`AdminScreen.openReady()`) before pressing, presses `ControlOrMeta+<key>`, and checks the page behind an overlay only after it closes.

## Traps

- The React Compiler (`react({ compiler: true })`, `oxc-transform-react`, which also compiles the `uilibs` sources) silently breaks Formisch field components: `app/components/form-fields.tsx` opens with `'use no memo'`, and any new component rendering a Formisch `field` needs it (only `e2e` `auth.spec.ts` catches a missing one). `build.rolldownOptions.onwarn` silences Rolldown's `MODULE_LEVEL_DIRECTIVE` for that line only. `oxc-transform-react` stays inside `@vitejs/plugin-react`'s peer range (`<0.157.0` for 6.3.0); bump both together.
- A component that shows a message calls `useMessages()`: the compiler memoizes on that per-language object, so `m` read from a prop or module constant keeps the old text.
- Base UI's `OTPField.Input` ignores `aria-label` on the first slot and names it from the root's label; `OTPField` turns a root `aria-label` into a hidden label. The Toast close button is `aria-hidden` until the stack is focused: find it by attribute.
- Base UI's `Button` gives a non-native render `role="button"`: a link is `Button render={<a />}`, which draws the anchor through `useRender` instead.
- `@storybook/tanstack-react` aliases `@tanstack/react-router`'s `Link` to a mock that renders a plain `<a>`, calls `preventDefault`, and drops `ref` and `render`, so a story never navigates through it. A story that needs a real route builds its anchor from `useLinkProps` on a memory router (`link.stories.tsx`); the real router `Link` is covered by the webapp E2E.
- Per-breakpoint plays use `contracts/viewport-frame.tsx` (an iframe of a given width with the page styles copied in; `frameOf` returns its `computed`): `useMediaQuery` and a story's own media queries read the parent window, so a hook test sets the width with `page.viewport` instead.
- A story `Axis` name is never camelCase: `data-colorMode` makes React log a console error, and `.storybook/preview.tsx` fails a story that logs one (use `mode`, `radius`, `items`).
- `':dir(rtl)'` follows `dir` because the shared StyleX plugin keeps `:dir()` through lightningcss (issue-00007, resolved); a mirrored icon uses it, spacing and position use logical properties. The `RightToLeft` stories (Calendar, data grid) fail if the plugin option goes. `Contracts/Right to left` (`src/contracts/rtl.stories.tsx`) places every inline-edge part under `dir="rtl"`, and `src/styles/logical-properties.test.ts` bans a physical margin, padding, border, radius, or `textAlign` outside `Sheet`, `Drawer`, and the data-grid editor metrics (`stylex-authoring.md`, "Logical, not physical").
- Axe runs after a story's `play`, when a popup the play opened is closed again: a popup that must be checked has an `Open` story that leaves it open.
- Storybook's canvas overlay (`.storybook/decorator.tsx`) sits inside the story root: scope role queries with `within(...)`.
- Do not run Storybook and the uilibs Vitest run together: they share the StyleX plugin and one run reported "Invalid empty selector".
- Sum the entry with its static imports (`just size`), not the chunk: a root provider or barrel import adds weight elsewhere.
