## Objective

The owner listed six leftovers after plan 00012: the flaky `RightToLeft` story and the removed `viewport.defaultViewport` parameter (`issue-00009`), the data grid's row and resize keys that were never compared with the WAI-ARIA Authoring Practices, two components named `ProgressIndicator`, a body font hard-coded in `globals.css`, and an unverified data grid focus ring. After this plan the test window is a Storybook global that the gate itself verifies, the dots component is `StepDots`, the page font is read from the `fontFamily` token, and the grid has a visible focus indicator in every state, a separator that satisfies ARIA 1.2, row paging keys, and a resize direction that follows `dir`. The plan changes no design token value, adds no dependency, grows no JavaScript in the webapp entry chunk, and does not push.

## Decisions

- **D1 (2026-11-26): the test window is `initialGlobals.viewport` as an object, set only under test, and the gate verifies it.** The Vitest addon reads the global first and `defaultViewport` only as a fallback, so moving to the global ends the manager warning and the dependence on a removed parameter, and the experiment above shows the 390 px gate still fails a wide story. A string global silently disables the gate, so `afterEach` also fails a story whose `window.innerWidth` differs from the width its viewport global names; that guard turns the next silent change into a red run. A story that needs room sets `globals: { viewport: { value: 'desktop', isRotated: false } }`. Cost: the story-level global also frames those two stories at 1200 px in the Storybook UI. Rejected: an unconditional `initialGlobals.viewport` — it would shrink the Storybook UI canvas to 390 px for every story, while the UI is fluid today (1100 px). Rejected: keeping `defaultViewport` and ignoring the warning — it works only through the addon's fallback and the owner's own issue says the warning may be hiding a real one. Rejected: the string form the message suggests — it makes the gate vacuous.
- **D2 (2026-11-26): the `RightToLeft` story keeps asserting the end state and gets `timeout: 10_000`.** A transition's end value is the assertion, so a longer timeout does not loosen it, and it is the repo's own precedent (`command.stories.tsx:432`). Rejected: reading the style without waiting — the 200 ms transition would make it fail on every run. Rejected: disabling the transition in the story — it would stop testing the shipped rule.
- **D3 (2026-11-26): the dots component is renamed `StepDots`; the Base UI part keeps `ProgressIndicator`.** The base name mirrors Base UI's `Progress.Indicator` like its siblings `ProgressTrack`, `ProgressLabel`, and `ProgressValue`, and `progress.mdx` ties them to it, so the odd one out is the extra component. `StepDots` shares no word with `Progress`, `Pagination`, or `Carousel`, and says what it draws (the position in steps or slides). Everything follows the name: `StepDotsProps`, `StepDotsLabels`, `StepDotsColor`, `StepDotsSize`, `stepDotsStyles`, `stepDotsSizes`, `stepDotsMedia`, folder `extra/step-dots/`, story title `Extra Components/StepDots`. Rejected: renaming the base part to `ProgressFill` — it breaks the Base UI part naming that the docs rely on. Rejected: `DotIndicator`, `ProgressDots` — the first keeps the word "Indicator" that caused the clash, the second keeps "Progress".
- **D4 (2026-11-26): the body font is read through a defined custom property name, `--font-body`, declared next to `fontFamily`.** StyleX lets a `defineVars` key that starts with `--` choose its own property name (verified in the compiler source and by a scratch compile), so a plain `.css` file can read the token without a hashed name. The mechanism costs one CSS rule and no JavaScript, so the 151.0 KB gzip entry is untouched (`just size` counts JS). `tokens.stylex.ts` gets `export const fontFamilyName = stylex.defineVars({ '--font-body': fontFamily.body })`, and `globals.css` becomes `font-family: var(--font-body)`; the `@font-face` name in `fontface.css` stays literal because a font-face rule cannot use a variable. Rejected: setting the font from `ThemeProvider` or `ThemeScript` — both are JavaScript in the entry chunk, run after first paint, and would still have to import a hashed token. Rejected: a `--` key inside `fontFamily` itself — it changes the accessor of 35 call sites (`fontFamily['--font-body']`) for one reader. Cost: `fontFamilyName` is an export with one reader (a CSS file); the comment in the token file says so.
- **D5 (2026-11-26): three APG differences are kept, not fixed.** `Enter` on a separator resets the width instead of collapsing the column: a collapsed column is a 20 px sliver, hiding a column already has a menu entry, and reset is the double-click twin that keyboard users otherwise lack. `Space` activates a clickable row because the row is the only widget in it and a selection checkbox exists for selecting. Clickable rows stay `row`s in a `table` without a grid role: a grid role makes every cell a focus target and changes the whole keyboard model. Each is written into `architecture.md` with a reopening trigger (RI-5 in the roadmap, unlocked by the screen reader pass RI-1), and `data-grid.mdx` says so.
- **D6 (2026-11-26): the container ring is CSS, not behavior.** A grid focused with no active cell draws the library focus ring (`stroke.ring2`, `foregroundPrimary`, inside the table) through `:focus-visible:not([aria-activedescendant])` (the compiler accepts the compound key, scratch compile 2026-11-26) and gives it up the moment a cell is active, so the cell ring is never doubled. The inline `outline: none` at `data-grid-cell.tsx:1049-1054` is removed. The cell ring stays 1 px: it shares the range-edge overlay, its 3:1 contrast is covered (`contrast.test.ts` asserts `foregroundPrimary`), and 2.4.7 asks for visible, not thick. Rejected: focusing the first cell on entry (the APG's usual form) — it fires `onCellSelectionChange` on a bare Tab and changes the editing flow; parked as RI-5. Rejected: a thicker cell ring — it moves every selection edge by a pixel.
- **D7 (2026-11-26): the resize direction is derived from the computed `direction` of the handle.** The grid already owns the drag math, so it reads `getComputedStyle(handle).direction` at event time (no state, no effect), mirrored again for an end-pinned column as before. `columnResizeDirection` is no longer read by the library (no backward compatibility); the two RTL stories keep passing it and stay green, and a new story proves the derived default without it. This closes the plan-00012 deviation ("the widening arrow follows the option, not `dir`") and the APG's physical rule (the arrow that points where the edge moves). Rejected: a `DataGrid` prop — a second place to forget. Rejected: Base UI's `useDirection` — it reads a provider, not the page, and the grid works without one.
- **D8 (2026-11-26): two tracks, and the viewport phase runs first and alone.** Track C (rename, font) and Track D (the data grid) have disjoint file sets. The viewport phase changes every story's window, so its gate is the whole suite and cannot share a tree with a track that is editing. Rejected: parallel phases inside Track D — phases 5 to 8 share `data-grid-table-head.tsx`, `data-grid-table.stylex.ts`, `data-grid-labels.tsx`, `data-grid.mdx`, and story files. Rejected: worktrees and orbs — one checkout, as the owner ruled.
- **D9 (2026-11-26): no backward compatibility.** `StepDots` replaces the old import path (`uilibs/extra/progress-indicator` is removed), `defaultViewport` is removed, `columnResizeDirection` stops being read, and `labels.columnWidth` is a new required label with an English default.
- **D10 (2026-11-26): a finding that does not reproduce closes with its evidence.** Phases 5, 6, 7, and 8 each start with a play that fails on the current code; a play that cannot fail means the finding was wrong and its phase closes as `false_positive` with the numbers.

## Execution rules

- **Nothing runs before the owner's go-ahead**, and then phase by phase: each phase's heading names its suggested commit message, and the go-ahead authorizes that phase's one commit and nothing else. After the last phase the coordinator stops and recommends the closing state; it does not push.
- **Branch.** The owner has not asked for one; work on `main` only if the owner says so, otherwise cut `fix/uilibs-leftovers` from `main` at `f2e3bb9`. Never push, rewrite history, `stash`, `reset`, `checkout .`, `clean`, or `--no-verify`.
- **Threads.** The thread the owner names is the **coordinator**; it runs wave 0 and wave 2 itself. For wave 1 it starts one thread per track with `create_thread` on the local runner (`executor: runner`, `working_directory` this checkout, no `worktree`, never an orb), two at most. A track thread runs only its phases in order and reports each commit hash to the coordinator with `send_thread_message`. With one thread, run the phases in numeric order.
- **Only the coordinator edits this plan, `index.md`, `issue-00009`, the roadmap, the handover, and the shared agent docs** (`frontend.md`, `architecture.md`, `packages/uilibs/AGENTS.md`). Track C edits `stylex-authoring.md`, `components.mdx`, and the two `frontend.md` and `architecture.md` lines that name `ProgressIndicator`, and no thread but Track C touches them in wave 1; Track D leaves its agent docs to phase 10.
- **Commit protocol in a shared tree (every thread, every phase):** record `git status --porcelain` before the first edit (files already modified belong to someone else); edit only the phase's paths; format and lint only those paths (`pnpm exec oxfmt --write <paths>`, `pnpm exec oxlint <paths>`, never `pnpm format`); stage explicit paths and commit with `git commit -m "<message>" -- <paths>`; if `.git/index.lock` exists wait 5 seconds and retry for up to a minute, never delete it; `git show --stat HEAD` must list only the phase's paths.
- **Shared-tree hazards.** Typecheck is whole-package: an error in a file you do not own is the other track's work in progress, so wait and rerun. A scoped run is `pnpm --filter uilibs exec vitest run --project storybook --project storybook-dark <paths>` (and `--project unit <path>`). Never run Storybook and a test at the same moment, never run `storybook:build` from a track (the coordinator builds at wave close), and run the full suite only when no track thread is active.
- **Experiments are reverted.** A scratch edit (a mutation check, a probe story) is copied aside first and restored byte for byte, and `git status` must be clean of it before the commit.
- **Per-phase validation runs before the phase's commit.** A UI change is also inspected: light and dark screenshots of the affected state, viewed. Sample data is Dan Brown and Harry Potter. No new dependency.
