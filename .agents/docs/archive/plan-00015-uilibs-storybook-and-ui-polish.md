## Objective

The owner's list of 13 items (Storybook errors, layout defects in ButtonGroup, Calendar, ToggleGroup, Resizable, and the data grid in a Card, plus motion, toast, font, and docs-theme work) was inspected in the tree and in a running Storybook on 2026-11-28. After this plan the Docs pages render from a build that cannot serve a stale story index, every defect the owner screenshotted is fixed and covered by a story assertion, the toast, tabs, and form controls have motion that is quiet and reduced-motion safe, and the position stories actually show each position. The plan does not change a token, add a dependency, or touch the SPA's serving.

## Current state: the root cause of each item

Verified on `main` at `2802d4c` (PR #8 merged, tree clean): a Storybook dev server on `:6107` over the tree, the built `apps/server/storybook`, and a headless Chromium driving both. Where a claim is a hypothesis it says so.

1. **Docs pages fail with "Invalid value passed to the 'of' prop" (AlertDialog, Dialog, Sheet).**
   - _Not a defect in the tree._ A scan of all 80 Docs entries on a fresh dev server found no failing page (three text hits were the word `FieldError` in the Field, Form, and Textarea pages).
   - _Reproduced the exact message from a stale index._ The built Storybook served with an `index.json` that lacks the `--short-window` entries (what a browser holding the pre-plan-00014 index has) while the JS chunks are new: Dialog Docs shows the owner's error; restoring the current index renders it. `alert-dialog.mdx:83`, `dialog.mdx:71`, and `sheet.mdx:67` are the only pages that embed `Stories.ShortWindow`, a story plan 00014 added (phases 34 and 35); every other page references only stories the old index also had. The owner's sidebars show no "Short window" under AlertDialog or Dialog although `index.json` lists them: the manager is reading the old index too.
   - _Cause._ `apps/server/src/transport/storybook.rs:25` calls `memory_serve::load!("storybook").index_file(None).into_router()` with the crate's defaults: every non-HTML file gets `Cache-Control: max-age=604800, stale-while-revalidate=86400` (memory-serve 2.4.0 `options.rs:43-46`; `enable_hashed_routes` is off), HTML gets `max-age=300`. `index.json`, `sb-manager/*.js`, `sb-addons/*`, `project.json` and `vite-inject-mocker-entry.js` are not content-hashed, so a rebuild reaches a browser up to eight days late and the preview (new hashed chunks) disagrees with the manager and the index (old).
   - _Not proved:_ the owner's browser cache itself. The inference rests on the exact reproduction, the three sidebars, and the headers in the crate source; phase 1 checks the served headers with `curl`.
2. **Tabs have no transition.** `tabs.stylex.ts` gives the active tab a background swap only (the 150 ms colour transition of `controlPress`); `tabs.component.tsx` renders no `Tabs.Indicator` (its header comment lists it, no export uses it) and the panel mounts and unmounts instantly. Base UI 1.9.0 provides `Tabs.Indicator` (`--active-tab-left|top|width|height`) and `data-starting-style`, `data-ending-style`, and `data-activation-direction` on `Tabs.Panel` (`tabs/indicator/TabsIndicatorCssVars.d.ts`, `tabs/panel/TabsPanelDataAttributes.d.ts`).
3. **Toast position and colour.**
   - _Position._ The `Position` story renders the toast at `[left 16, top -58, 320 × 74]` in a 500 px viewport: entirely off-screen. `toastStyles.viewport` is a zero-height fixed box and each toast is `position: absolute; bottom: 0` with stack transforms that assume a bottom anchor (`toast.stylex.ts:9-14,26,52-58`); the story moves the viewport to `top: 16` through `style` and the toast still grows upward out of it. The default bottom-right toast also sits on Storybook's own canvas bar (the S/M/L/XL pill and the LTR button): a Storybook-only overlap.
   - _Colour._ `toastColors` changes `borderColor` only (`toast.stylex.ts:121-128`); title, description, close button, and surface stay neutral, so a `success` and a `neutral` toast differ by a 1 px edge.
4. **The loading toast has no loading state.** Base UI sets `data-type="loading"` on the toast (measured) and nothing styles it; the text is a `descriptionText` paragraph (faded), so "Sealing the cryptex…" reads as inert text. The hand-over to success only changes the text and height.
5. **The Toolbar's ToggleGroup corners are not concentric.** In `With a toggle group` the toolbar is `radius.large` (10 px) with `padding: unit.x1` (4 px), so an inner corner should be 6 px; the joined group's ends are a hard-coded `radius.large` (`toggle-group.stylex.ts:31-41`, 10 px, measured `10px 0 0 10px`), the neighbouring `Accio` button is 8 px (`radius.medium`), and the group's items are 36 px tall against `Accio` at 32 (measured: items 36, `Accio` 32; the story passes no `size`). `Toggle` itself is `radius.large` (`toggle.stylex.ts:12`) while Button, Input, Select, and every `controlBase` control are `radius.medium`.
6. **Position stories are cornered, and they flip.** Tooltip `Sides` (`tooltip.stories.tsx:128`), Popover `Placement` (`popover.stories.tsx:128`), PreviewCard `Sides` (`preview-card.stories.tsx:155`), Sheet `Sides` (`sheet.stories.tsx:165`) and Toast `Position` (`toast.stories.tsx:220`) put each trigger in a top-left `Axis` cell. The tooltip and popover docblocks admit it: "the popup flips when the canvas leaves it no room, so the side is not asserted". The demo does not show the position it names.
7. **`UIProvider` has a sidebar entry and one story.** `src/base/provider.stories.tsx` (title `Base Components/UIProvider`, one `RightToLeft` story with a `play`) is embedded by `.storybook/stories/theming.mdx:2,199` and described in `frontend.md` ("Three pages sit outside the components"). The play is the only test that `UIProvider direction='rtl'` reaches a Base UI slider and select.
8. **The Arabic story is Latin, in text and in face.** `ArabicLeftToRight` (`calendar.stories.tsx:775-778`) passes `lang='ar'` and no `locale`: measured heading "November 2026" and weekdays "Su Mo Tu…" (`react-day-picker` takes its text from `locale`, not `lang`). ## Decisions

Every decision is the recommendation of this plan; the owner overrides by naming the decision.

- **D1 (2026-11-28): the static Storybook is served with `Cache-Control: no-cache` for every file, HTML included.** Fix for item 1. `no-cache` still lets the browser revalidate with the ETag memory-serve already sends, so an unchanged file costs a 304. Cost: one revalidation request per file per page load of a 16 MB site served from RAM on a dev tool. Rejected: `no-cache` for `index.json` and the `sb-*` files only (a list to maintain; hashed chunks are already safe, but the rule "Storybook is never stale" is simpler and has no list). Rejected: `enable_hashed_routes` (it adds a second, immutable route per file but does not change the headers of the original route Storybook links to). Rejected: a cache-busting query on `index.json` (Storybook owns the URL).
- **D2: a guard test renders every docs entry; it is a Node script, not a story.** Fix for "check every Docs page". `scripts/check-docs-render.ts` reads `index.json` from a served static build, opens each `docs` entry in Chromium (Playwright is a declared devDependency), fails on the `of` error text or a console error, and toggles the theme on one page. It runs after `storybook:build` in the CI `checks` job. Rejected: Vitest stories (docs entries are not tests; the gate count must not move, `frontend.md`). Rejected: relying on the existing story gate (it never opens a docs page: this is how the error shipped unnoticed).
- **D3: the data grid page is named by `<Meta name='Docs'>`, not by renaming files.** Fix for item 11. Rejected: renaming `data-grid.mdx` to `data-grid-basics.mdx` (the page covers the whole grid, not the Basics file) and moving the CSF (large churn for a label).
- **D4: the `UIProvider` story moves to `Contracts` instead of being deleted.** Fix for item 7. The play is the only proof that `direction` reaches Base UI; the owner's complaint is the component-list entry and the story clutter, which a `Contracts/Right To Left` story removes. `theming.mdx` embeds it from there. Cost: the contract list gains one story. Rejected: deleting it outright (the assertion would be lost, and `frontend.md` records a mutation test on it).
- **D5: the docs container reads the live global on mount, after a reproduction attempt.** Fix for item 13. If the cache-fixed build and a stale-cache simulation reproduce the symptom, the phase records "closed by D1, no code" and keeps only the guard's theme assertion; otherwise the container reads `userGlobals` from the preview store on mount instead of the iframe URL. Rejected: changing the container blind (the symptom is not reproduced; a speculative change would ship unproved).
- **D6: `Toaster` gets a `position` prop (`bottom-right` default, `bottom-left`, `bottom-center`, `top-right`, `top-left`, `top-center`); the raw `style` override is no longer the way to move it.** Fix for item 3. The viewport and every toast take the edge from the prop (top positions anchor `top: 0` and stack with the transform signs reversed; centres use `insetInline: 0; margin-inline: auto`). Physical `left` and `right` stay, as `theming.mdx` documents ("Toast keeps the screen side it is given"). Cost: a new public prop and mdx row. Rejected: fixing the story's `style` only (every consumer has the same problem). Rejected: per-direction logical sides (contradicts the documented rule).
- **D7: a toast's status shows in three quiet places: a faded surface tint, a leading glyph, and the title colour; the edge stays.** Fix for item 3. Tint is `backgroundXFaded` over the overlay surface, the glyph and title use `foregroundX`, description and close stay neutral so the text keeps its contrast; neutral is unchanged. All tokens exist (`colors.stylex.ts:14-37,54`). Glyphs reuse the library icon set (check, warning, error, info); `aria-hidden`, since the title carries the meaning. Rejected: a solid fill (loud, and fails "still subtle"). Rejected: colouring the whole text (the description's contrast on tint is the risk; measured in the phase in both themes).
- **D8: the loading toast shows the library `Spinner` in the glyph slot and the same slot becomes the outcome glyph.** Fix for item 4. The slot cross-fades (opacity, 150 ms, reduced-motion: no fade) and the toast keeps its width so the height change of the new text is the only movement. The text of a loading toast takes the title style, not the faded description style. Rejected: a progress bar (the promise has no progress). Rejected: a new loader component (`Spinner` exists and already slows under reduced motion).
- **D9: Tabs get one sliding indicator and a panel entrance, with no new prop.** Fix for item 2. `TabsList` renders `Tabs.Indicator` itself; `pills` and `pills-raised` use it as the active pill (the trigger's own active background goes, so there is one source), `bordered` and `borderless` use it as the underline (the trigger's active bottom border goes). It moves with `transitionProperty: left, width` (or `top, height` when vertical) on `duration.medium` and `easing.standard`. The panel fades in and rises 4 px from `data-activation-direction` through `data-starting-style`; under `prefers-reduced-motion` it is opacity only and the indicator moves instantly. Forced colours keep the active edge (the existing media query is kept on the indicator). Cost: first paint draws the indicator after Base UI measures the active tab. Rejected: a CSS-only underline on the trigger (cannot slide between triggers). Rejected: a View Transition (not available in WebKit for DOM updates on every tab switch, and it would animate the whole panel).
- **D10: `ButtonGroup` text children split the group into runs.** Fix for item 14. A bare string or number is wrapped in a centred inline-flex span with `paddingInline: unit.x2` and is not a member; positions are computed per run of consecutive element children, so `Accept or Decline` is two standalone buttons around centred text. `ButtonGroupText` stays the bordered, joined label. Cost: a contract change (a text child no longer sits inside one joined run), recorded in `button-group.mdx` line 88. Rejected: counting text as a member (it has no edge to join and leaves the open edges). Rejected: forbidding text children (the mdx documents them).
- **D11: the `Group sets size and variant` story keeps its assertions on inheritance and moves the override into a second, labelled group.** Fix for item 15. The first group has every member inheriting `small`/`outline` and asserts equal heights; the second shows `size='large'` on one member with a caption that a mixed group is the caller's choice. The library is unchanged: the documented contract is "a member can still set its own". Rejected: making the group win over a member's `size` (breaks a documented contract to fix a demo).
- **D12: corners are concentric by token: `Toolbar` radius `xlarge` (12), `Toggle` and the joined `ToggleGroup` ends `medium` (8), and the story's toggles are `size='small'`.** Fix for item 5. 12 = 8 + 4 px padding, and 8 is what Button, Input, and Select already use. Visible side effect: a standalone `Toggle` goes from 10 to 8 px. Cost: that visible change on every Toggle. Rejected: only an inner radius of 6 inside a Toolbar (a context-read special case, and the Toggle would still disagree with Button elsewhere). Rejected: leaving the Toggle at 10 and the Toolbar at 14 (no such token).
- **D13: only the grip keeps the 3:1 colour; the Resizable rail and the `line` handle rest on `borderNeutral` and rise on hover and drag.** Fix for item 10. The rest rail is `colors.borderNeutral` (12 % black, close to the panel edges), hover is `borderControl`, drag and focus stay primary; the grip (pill, spring, capsule) keeps `borderControl` at rest, so the control's visible affordance meets WCAG 1.4.11 where it exists. Risk, stated: the `line` variant's only affordance is the line, so it rests on `borderControl` blended down no further than 3:1 over its panel; the phase measures both themes and, if `borderNeutral` fails 3:1 for `line`, `line` keeps `borderControl` at rest and only the rail behind the other variants softens. Rejected: a new token (tokens change only on the owner's decision).
- **D14: the Calendar root is `width: fit-content` (with `maxWidth: 100%`).** Fix for item 16. Rejected: capping the day cell (`maxWidth` on the button leaves the `td` highlight sized by the parent). ## Execution rules

- **Atomic commit per phase** is authorized; each phase names its commit message. The owner's "continue with wave N" authorizes every phase of that wave, one commit each, in the order of its track; nothing else.
- **Execution waits for the owner's explicit instruction.** After wave 3, the agent stops and recommends the closing commit (phase 22 is that commit if the owner already said so).
- **No backward compatibility, no legacy shims** (`AGENTS.md`): a replaced prop, story, or id is removed (the old `data-grid-basics--data-grid` links, the `Toaster` `style` position override, the `UIProvider` story).
- **No new dependency and no token change.** Every value comes from `src/styles/` tokens; a phase that needs a new token or package stops and asks.
- **Parallel threads: at most four per wave, one checkout.** Each track owns the files in its table row and never edits another track's files. A track stages explicit paths and commits with `git commit -m '…' -- <paths>`; on an index-lock error it retries and never removes the lock. No `git stash`, `checkout .`, or `reset`. Each track runs its own Storybook dev server on its own port (A 6101, B 6102, C 6103, D 6104; E 6101, F 6102, G 6103) and runs only scoped tests (`just test-ui <path>`); the full suites run in phase 23.
- **Per-phase validation runs before the phase's commit:** the phase's command, plus `pnpm --filter uilibs typecheck`, `pnpm lint`, `pnpm format --check` on the touched paths, and `just check-ui-docs` when an `mdx` or a Playground `include` changed.
- **A visible change is looked at, not only asserted.** Each phase that changes appearance captures the affected stories in light and dark (Playwright against the track's dev server, 390 px and 1100 px where it matters), views them, and fixes what is wrong before committing. Screenshots stay under `.amp/in/`.
- **Each phase that fixes a defect is red first:** the story assertion or script that fails on the current tree is written, run, and shown failing, then the fix makes it pass.
- **E2E** runs only where a flow changes; recorded n/a otherwise (phase 23 records it).
