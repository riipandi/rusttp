# StyleX `:dir(rtl)` matches `lang`, not `dir`

## Direction flips in uilibs follow `lang`, not the `dir` attribute

- status: resolved (2026-11-25)
  area: frontend/uilibs
  summary: StyleX compiles `':dir(rtl)'` into `:is(:lang(ae), :lang(ar), :lang(arc), :lang(bcc), :lang(bqi), :lang(ckb), :lang(dv), :lang(fa), …)`; the built Storybook CSS (`.output/storybook/assets/iframe-*.css`) holds the `:lang()` list and no `:dir(rtl)` selector. Four rules use it: `packages/uilibs/src/extra/calendar/calendar.stylex.ts:33` (`scaleX(-1)` on the month arrows), and `packages/uilibs/src/data-grid/data-grid-table.stylex.ts:432` and `:441` (expand chevron `rotate(0deg)` and `rotate(90deg)`) and `:863` (`rotate(180deg)`). A subtree with `dir="rtl"` and no Arabic, Hebrew, Persian, or similar `lang` (the Storybook direction toggle, an app that sets `dir` alone) draws the left-to-right transform. Found while building `BadgeAnchor`, whose first version used a `:dir(rtl)` variant and measured the badge on the wrong corner in an RTL wrapper; `BadgeAnchor` now uses logical insets (`badge-anchor.stylex.ts:14` says why).
  plan: none yet (plan-00011 phase 51 documents it on the theming page; phase 44 only worked around it)
  note: plan-00011 phase 51 re-checked it in the Calendar (2026-11-25, Chromium, `dir="rtl"` on a wrapper): the month arrows kept `transform: none`, and so did they with `lang="ar"` on the wrapper, because `react-day-picker` renders its root with `lang` set to the locale (`en-US`), which shadows the wrapper's `lang` (`svg.matches(':lang(ar)')` was false); the phase 51 RTL story (Field, Input, Select, Slider) does not draw a Calendar or a data grid, so it passes, and `theming.mdx` states the gap. Verified 2026-11-25 against the built CSS (zero `:dir(rtl)` occurrences, the `:lang()` list present). Not fixed in plan-00011 phase 44, on the owner's instruction.
  cause: found 2026-11-25; not StyleX. StyleX 0.19.2 emits `.x19axjrm:dir(rtl){transform:scaleX(-1)}`. `@stylexjs/unplugin` then runs lightningcss over the sheet with `targets: browserslistToTargets(browserslist())` (`unplugin/lib/core.js:36-49`), and the repo has no browserslist config, so the default query applies and lists Chrome 109. `:dir()` shipped in Chrome 120, so lightningcss lowers `:dir(rtl)` to `:is(:lang(ae), :lang(ar), …, :lang(yi))` (Chrome 109 is the only default entry that triggers it). The `:lang()` list is wrong both ways in Chromium 159, Firefox 159 and WebKit 27.2: `<div dir=ltr lang=ar>` flips, `<div dir=rtl>` does not. `react-day-picker`'s root `lang` (its locale, `DayPicker.js:257`) hiding a wrapper's `lang` was a secondary effect.
  resolution: `packages/plugins/src/stylex.ts` passes `lightningcssOptions.exclude |= 4` (lightningcss `Features.DirSelector`, a literal because the package does not depend on lightningcss) merged into a caller's own options, so every consumer keeps `:dir()` (688f057). The built Storybook CSS has four `:dir(rtl)` rules and no `:lang()` list; only those four rules changed (125.9 KB against 126.8 KB). `data-grid-table.stylex.ts` dropped the dead `':dir(rtl)': 'rotate(0deg)'` on `rowExpandChevron` (the collapsed class replaces the whole `transform`). Stories prove it in Chromium, Firefox and WebKit with `dir="rtl"` on a wrapper and no `lang`: Calendar `RightToLeft` (arrows `scaleX(-1)`), Calendar `ArabicLeftToRight` (`lang="ar"` under `dir="ltr"` stays unflipped), and data grid `RightToLeft` (collapsed chevron `rotate(90deg)`, expanded chevron down, pager arrows `rotate(180deg)`); each fails with the flag removed (dd9c9ea). `calendar.mdx` documents `dir` on the document or a wrapper; a `dir` prop on `Calendar` itself was probed once (arrows mirrored, the previous button on the right) but has no story. Chrome below 120 gets no flip. Rejected: a modern browserslist (a browser support policy, a separate decision), `:is([dir=rtl] *)` (wrong for `dir=ltr` nested in `rtl`), `useDirection()` variants (follow `UIProvider`, not the DOM `dir`), and `stylex.when.ancestor('[dir=rtl]')` (needs a StyleX marker class on the ancestor).
  trigger: None. Closed. A consumer that compiles `uilibs` with its own StyleX pipeline must pass the same lightningcss exclusion.
