# Shape

updated: 2026-11-19T22:18:41+07:00

The repository's shape: the layout, the toolchain, and the commands. Read once; return when a path or a command is needed.

## Layout

| Path                    | Role                                                                                                                                                                                                                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/<app>/`           | Deployable binaries and the composition root: CLI, module registration, lifecycle, the app's own migrations (`apps/<app>/migrations/`). `apps/server` (`rusttp-server`) is the default member (`Cargo.toml:4`). `src/transport/` is the HTTP surface (`mod.rs` composes it; `rpc.rs` Connect via `connectrpc` on `/rpc`, `http.rs` REST on `/api`, `spa.rs` the SPA via `memory-serve`, `static.rs` the HTML error page, `server.rs` the listener); `build.rs` points memory-serve at `apps/server/frontend` (gitignored). Its CLI (clap derive) lives in `apps/server/src/cmd/`: `mod.rs` holds `Cli` (global `--env-file`, `--config-file`) and dispatch, one file per command group owns its `Args` and `run`; commands follow `docs/commandline.md`, every one except `serve` is a placeholder that exits 1 with "not implemented yet", and the development-only `migrate:create|validate|reset|seed` exist only under `debug_assertions`.                                                                     |
| `crates/<name>/`        | Reusable framework libraries: kernel, database, observer, mailer, queue, scheduler, audit. No domain knowledge.                                                                                                                                                                     |
| `modules/<name>/`       | Domain modules (bounded contexts), one crate each.                                                                                                                                                                                                                                  |
| `api/connect/`          | Protobuf contracts.                                                                                                                                                                                                                                                                 |
| `api/specs/<area>/`     | Hurl HTTP specs, one directory per area.                                                                                                                                                                                                                                            |
| `packages/`             | pnpm workspace (`pnpm-workspace.yaml`): `webapp`, `emails`, `e2e`. `webapp` is a React SPA (Vite, TanStack Router file routes in `app/routes/` generating the gitignored `app/routes.gen.ts` (the Vite plugin in dev, `tsr generate` before `build` and `typecheck`, both reading `tsr.config.json`), TanStack Query; TanStack devtools in `app/routes/-devtools.tsx`, toggled with Shift+D and stripped from production builds by `@tanstack/devtools-vite`); `pnpm --filter webapp dev` serves `:5173` and proxies `/api`, `/rpc`, and `/healthz` to the Rust server (`BACKEND_URL`, default `http://127.0.0.1:3000`); `build` type-checks with `tsrs --noEmit --fast` (the Rust port of the TypeScript 7 checker; there is no `typescript` package in the workspace) then writes `apps/server/frontend/` (gitignored), which the server embeds in release builds; `public/` holds the favicon set (`favicon.svg` switches colour with `prefers-color-scheme`; `favicon.ico`/`favicon.png` are light-only rasters of it) and `manifest.json`. `emails` holds the email templates (jsx-email, inline `style` props, no Tailwind): `templates/<name>.tsx` exports `templateName`, `previewProps` (sample data), `templateProps` (Jinja-style `{{snake_case}}` placeholders, written without inner spaces) and `Template`, built from jsx-email components plus the project's in `components/*.tsx` (`layout.tsx`, `logo.tsx` drawn from table cells, `when.tsx` turning an empty-able placeholder into a `{% if %}` block through `Raw`, `rich-content.tsx` inserting a server-supplied HTML body (`{{content_html|safe}}`, with `{{content_text}}` for the text part) under scoped default styles for paragraphs, headings, lists, links, quotes, code, tables, and images, …); dark-mode styles target `data-dm` attributes because the inline plugin strips classes and `<style>`; `jsx-email.config.mjs` loads the url (UTM on valid URLs) and clean plugins and renders with inline CSS, minified when `NODE_ENV=production`, pretty otherwise; `pnpm --filter emails dev` (`node preview.ts`) previews on `:3030` without opening a browser, filtering jsx-email's info logs and the preview app's known warnings, `build` (`node build.ts`) compiles every template and writes `apps/server/emails/<name>.html` + `.txt` (gitignored, regenerated), `check <file>` runs the client-compatibility check. `e2e` is a Playwright suite (`playwright.config.ts`; screen objects in `screens/<area>/*.screen.ts` with specs beside them, registered as fixtures in `fixtures/test.ts`, routes in `utils/routes.ts`); unless `E2E_BASE_URL` is set it starts the Rust server and `vite preview` of the built SPA, and writes reports to `.output/`.                                                                                                                                                                                                                                          |
| `scripts/*.just`        | Task recipes imported by `justfile` (`task-development`, `task-quality`, `task-e2e`, `task-container`, `task-utilities`).                                                                                                                                                                                         |
| `container/`, `deploy/` | Compose and deployment templates. `container/compose.yaml` includes `compose-dev.yaml` (pgsql, redis, silo S3, mailpit) and `compose-sre.yaml` (ClickStack, cadvisor, redis-exporter; `container/clickstack/` holds its collector config, provisioning script, dashboards, saved searches, alerts; provisioning favorites every shipped dashboard and search, and alerts email the Mailpit inbox through a webhook). |
| `.agents/docs/`         | Agent ledger.                                                                                                                                                                                                                                                                       |
| `docs/`                 | Human-facing documentation.                                                                                                                                                                                                                                                         |

## Toolchain

- Rust `1.100.0` (`rust-toolchain.toml:13`), edition 2024 (`Cargo.toml:14`), workspace resolver 2.
- Formatting: `rustfmt.toml` (edition 2024, `max_width = 120`). A Claude Code `PostToolUse` hook (`.claude/hooks/format.sh`) formats every edited file inside the repository: `.rs` with `rustfmt`, `.md` with `rumdl fmt` (default rules, no line wrapping), and `.ts`/`.tsx`/`.js`/`.jsx`/`.json`/`.css` under `packages/` with the workspace-root `oxfmt`. Frontend style lives in `.oxfmtrc.json` (2 spaces, single quotes, no semicolons, sorted imports) and lint rules in `.oxlintrc.json` (type-aware through `tsrs-lint`, which oxlint picks up from the installed `tsrs`); both are installed at the pnpm workspace root. It needs `jq`; a missing formatter is skipped silently.
- Workspace lints (`Cargo.toml:17-20`): `missing_docs = "warn"`, `unreachable_pub = "deny"`, `private_interfaces = "deny"`. Each crate opts in with `[lints] workspace = true`.
- Build flags (`.cargo/config.toml`): `target-cpu=native`; `lld` on the musl and aarch64-gnu targets.
- Frontend: pnpm `12.21.0` (`package.json`).
- Developer tools: `just`, `cargo-nextest`, `rumdl`, `hurl`, `watchexec`; optional: `cargo-hack` (feature combinations), `cargo-deny`, `sqlx-cli`. Check that a tool is installed before relying on it; do not install one unasked.

## Commands

Run every gate through `just` (`justfile` imports `scripts/task-*.just`; `just` alone lists the recipes).

| Gate                 | Recipe                              | Runs                                                                                                             |
| -------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Format               | `just format` / `just format-check` | `cargo fmt --all` + `rumdl fmt .` + `pnpm format` (oxfmt on `packages/`; `--check` for all three; config in `.rumdl.toml`, `.oxfmtrc.json`)                                  |
| Check                | `just check`                        | `cargo check --workspace --all-targets`                                                                          |
| Lint                 | `just lint`                         | `cargo clippy --workspace --all-targets -- -D warnings` + `pnpm lint` (oxlint on `packages/`)                                                          |
| Test                 | `just test`                         | `cargo nextest run --workspace` (falls back to `cargo test --workspace`); E2E has its own `e2e-*` group (below)                                         |
| All of the above     | `just verify`                       | format-check, check, lint, test                                                                                  |
| API specs            | `just test-api [url]`               | `hurl --test` over `api/specs/**/*.hurl`, `base_url` defaults to `http://127.0.0.1:3000`; needs a running server |
| Feature combinations | —                                   | `cargo hack check --each-feature -p rusttp-server`, only when `cargo-hack` is installed                          |

Other recipes: `dev` (runs `serve` in a watchexec restart loop), `run <command>` (any app CLI command, e.g. `just run serve --bind 0.0.0.0:3000`), `build` (release, then prints the binary size) and `start` (runs `serve` from the release build), `deps`, and the `compose-*` (up, down, restart, exec, cleanup) / `docker-*` (build, images, run, shell, push) container tasks (`container/compose.yaml`, `deploy/Dockerfile`). Utility: `generate-key`, `cleanup`. Email (group `email` in `scripts/task-development.just`, `packages/emails`): `email-dev` (preview on `:3030`), `email-build` (writes `apps/server/emails/`), `email-check <name> [args]` (client compatibility of `templates/<name>.tsx`, e.g. `--use-preview-props`). E2E (`scripts/task-e2e.just`, Playwright in `packages/e2e`): `e2e-test [args]` (headless, all projects; e.g. `--project Chromium`), `e2e-chrome` / `e2e-firefox` / `e2e-safari` / `e2e-mobile` (headed, one project), `e2e-ui`, `e2e-report`, `e2e-install` (browsers, once).
