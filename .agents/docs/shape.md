# Shape

updated: 2026-11-20T06:05:00+07:00

The repository's shape: the layout, the toolchain, and the commands. Read once; return when a path or a command is needed.

## Layout

| Path                    | Role                                                                                                                                                                                                                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/<app>/`           | Deployable binaries and the composition root: CLI, module registration, lifecycle, the app's own migrations (`apps/<app>/migrations/`). `apps/server` (`rusttp-server`) is the default member (`Cargo.toml:4`). `src/transport/` is the HTTP surface (`mod.rs` composes it; `rpc.rs` Connect via `connectrpc` on `/rpc`, `http.rs` REST on `/api`, `spa.rs` the SPA document through `vixum` with the assets from `memory-serve`, `static.rs` the HTML error page, `server.rs` the listener); `build.rs` points memory-serve at `apps/server/frontend` (gitignored), seeding it with a stub manifest (entry `stub/default.js`) and a `null` route table when the SPA is not built; `stub/head.html` and `stub/body.html` are the document shell, `stub/error.html` the panic page. Its CLI (clap derive) lives in `apps/server/src/cmd/`: `mod.rs` holds `Cli` (global `--env-file`, `--config-file`) and dispatch, one file per command group owns its `Args` and `run`; commands follow `docs/commandline.md`, every one except `serve` is a placeholder that exits 1 with "not implemented yet", and the development-only `migrate:create|validate|reset|seed` exist only under `debug_assertions`.                                                                     |
| `crates/<name>/`        | Reusable framework libraries: kernel, database, observer, mailer, queue, scheduler, audit. No domain knowledge. `vixum` renders the SPA document (`Shell`: the app's static markup; `Page`: per-page head and status; the entry tags from the build manifest, or Vite's `transformIndexHtml` in dev), answers 404 where the TanStack route table has no route (`Route`), and proxies the rest to Vite in dev.                                                                                                                                                                     |
| `modules/<name>/`       | Domain modules (bounded contexts), one crate each.                                                                                                                                                                                                                                  |
| `api/connect/`          | Protobuf contracts.                                                                                                                                                                                                                                                                 |
| `api/specs/<area>/`     | Hurl HTTP specs, one directory per area.                                                                                                                                                                                                                                            |
| `packages/`             | pnpm workspace (`pnpm-workspace.yaml`): `webapp`, `emails`, `e2e`, `uilibs`, `plugins`. `plugins` holds the Vite plugins shared across packages (`src/rust-server.ts`, `src/vixum.ts`, `src/stylex.ts`), imported as `plugins/<name>` through its `exports` map (a `workspace:*` devDependency of each consumer). `webapp` is a React SPA (imports inside it use `#/*`, which is `app/*`, through `tsconfig.json` paths and Vite's `resolve.tsconfigPaths`; Vite, TanStack Router file routes in `app/routes/` generating the gitignored `app/routes.gen.ts` (the Vite plugin in dev, `tsr generate` before `build` and `typecheck`, both reading `tsr.config.json`), TanStack Query; TanStack devtools in `app/routes/-devtools.tsx`, toggled with Shift+D and stripped from production builds by `@tanstack/devtools-vite`); `pnpm --filter webapp dev` runs Vite on `127.0.0.1:5173` (HMR socket included) and, through `plugins/rust-server`, builds and runs the Rust server (`cargo build -p rusttp-server`, then `target/debug/rusttp-server serve` with `VITE_DEV_SERVER`); the browser opens the server on `:3000`, which renders the documents and proxies modules and assets to Vite; a `.rs`/`.toml`/`.sql` change, or one to the `apps/server/stub` shell, rebuilds, then starts the new server beside the old one and retires the old one; `build` type-checks with `tsrs --noEmit --fast` (the Rust port of the TypeScript 7 checker; there is no `typescript` package in the workspace) then writes `apps/server/frontend/` (gitignored: assets, `.vite/manifest.json`, `routes.json`), which the server embeds in release builds; there is no `index.html` (the build input is `app/main.tsx`; `plugins/vixum` is the Vite side of the server-rendered document); `public/` holds the favicon set (`favicon.svg` switches colour with `prefers-color-scheme`; `favicon.ico`/`favicon.png` are light-only rasters of it) and `manifest.json`. `emails` holds the email templates (jsx-email, inline `style` props, no Tailwind): `templates/<name>.tsx` exports `templateName`, `previewProps` (sample data), `templateProps` (Jinja-style `{{snake_case}}` placeholders, written without inner spaces) and `Template`, built from jsx-email components plus the project's in `components/*.tsx` (`layout.tsx`, `logo.tsx` drawn from table cells, `when.tsx` turning an empty-able placeholder into a `{% if %}` block through `Raw`, `rich-content.tsx` inserting a server-supplied HTML body (`{{content_html|safe}}`, with `{{content_text}}` for the text part) under scoped default styles for paragraphs, headings, lists, links, quotes, code, tables, and images, …); dark-mode styles target `data-dm` attributes because the inline plugin strips classes and `<style>`; `jsx-email.config.mjs` loads the url (UTM on valid URLs) and clean plugins and renders with inline CSS, minified when `NODE_ENV=production`, pretty otherwise; `pnpm --filter emails dev` (`node preview.ts`) previews on `:3030` without opening a browser, filtering jsx-email's info logs and the preview app's known warnings, `build` (`node build.ts`) compiles every template and writes `apps/server/emails/<name>.html` + `.txt` (gitignored, regenerated), `check <file>` runs the client-compatibility check. `uilibs` is the shared React component library (StyleX styles, Base UI primitives; source-sharing: consumers import `uilibs/<path>` straight from `src/` through the `exports` map and compile it with their own Vite): `src/base/` (Base UI wrappers), `src/extra/` (composed components, data-grid, kanban, sortable), `src/charts/`, `src/icons/`, `src/styles/` (StyleX tokens, colors, themes), `src/theme/` (provider and switcher), `src/hooks/`, `src/assets/` (reset, fonts, `globals.css`), `src/contracts/` (story-only checks that span components: the `ref` contract and the shared control-size story, with the helper `control-sizes.tsx`); each component is `<name>/{<name>.component.tsx,<name>.stylex.ts,<name>.stories.tsx,index.ts}`; the component inventory is `ui-components.md`; `pnpm --filter uilibs storybook` serves Storybook on `:6006` (`localhost`/`127.0.0.1` only: `core.allowedHosts` in `.storybook/main.ts` is a list, not `true`, because `true` lets any open website read sources and write files through the WebSocket and MCP server), `storybook:build` writes `.output/storybook`, `test` runs the stories as Vitest browser tests (Chromium; `pnpm --filter e2e install-browsers` first) and fails on an axe violation (the gate: `.storybook/preview.tsx`; `STORYBOOK_A11Y_GATE=todo` or `off` relaxes it for a local run, and the only allowlisted element is Base UI's focus guard); the StyleX Vite plugin is `packages/plugins/src/stylex.ts`, used by `uilibs`' own Vite config and by `webapp`'s (which compiles the `uilibs` sources in place and passes the same plugin to `vixum`'s `plugins` option, because the build-time route reader loads the route modules and StyleX throws uncompiled); `webapp` takes the library from `uilibs/<path>` (`UIProvider` and `ThemeProvider` wrap the root in `routes/__root.tsx`, `uilibs/assets/globals.css` is its only global CSS, page styles live in `app/styles/pages/<page>.stylex.ts` and shared element styles in `app/styles/element/<name>.stylex.ts` (the `(auth)` group is a layout route, `routes/(auth)/route.tsx`: a brand panel plus the form column, styled by `styles/pages/auth.stylex.ts`, with login, signup, forgot-password, reset-password, verify-email, email-verified, mfa, and device as placeholder pages that fill the column and continue to each other without a backend (forms are Formisch (`@formisch/react`) with Valibot schemas in `app/schemas/<form>.schema.ts` (`fields.schema.ts` holds the rules several forms share): a route calls `useForm({ schema, initialInput })`, renders each field as `<Field of={form} path={['email']}>{(field) => <TextField field={field} … />}</Field>` with the components in `app/components/form-fields.tsx` (Base UI `Field` around the `uilibs` controls), and submits through `handleSubmit(form, onValid)` on a `uilibs` `<Form noValidate>`; validation runs on submit, then on input (Formisch's default), `noValidate` keeps the browser's own checks out of the way, and an email field uses `inputMode`, not `type='email'`, because native validity would block the submit before Valibot runs; login and signup carry the captcha field and the `SocialButtons` placeholder from `app/components/`, signup has first and last name in two columns, and `StatusIcon` marks the verify-email and email-verified pages); `layout.stylex.ts` is the page shell every route uses: `root`, `container`, `header`, `brand`, `main`, `center`, `footer`; `app/components/logo.tsx` is the logo mark), each exporting `styles` and imported as `#/styles/...` (a route applies them with `stylex.props`, there is no wrapper component); a route that outgrows one file becomes a folder (`routes/(app)/dashboard/index.tsx` with `-summary.tsx`, `-loans-table.tsx`, and `-data.ts` beside it; what several routes of a group share sits at the group level, `routes/(app)/-header.tsx`, and the small-screen drawer both layouts share is `app/components/nav-sheet.tsx` (`NavSheet`, styled by `styles/element/nav-sheet.stylex.ts`: profile, grouped entries, account entries pinned to the bottom; each layout passes its own groups, e.g. `routes/admin/-nav.ts`), and each group owns its account menu, `routes/(app)/-user-menu.tsx` (the avatar; Account and Security link to `/settings/*`) and `routes/admin/-user-menu.tsx` (the sidebar account avatar button, with a short name beside it in the drawer; personal entries only: Account and Security under `/admin`, Back to app, Theme, Sign out); the `-` prefix keeps these files out of the route tree; `routes/-boundaries.tsx` holds the not-found and error pages, and each wraps itself in `ThemeProvider` because the root's error component replaces the root, providers included, so a reload would otherwise render it light). Three layouts: `/` (`routes/index.tsx`, the landing page, no group), the customer dashboard `routes/(app)/` (a pathless group: `route.tsx` renders the top navigation above the page; pages `/dashboard`), and the admin dashboard `routes/admin/` (URL prefix `/admin`: `route.tsx` renders the sidebar `-sidebar.tsx`, styled by `styles/element/sidebar.stylex.ts` and `styles/pages/admin.stylex.ts`, beside the page; the sidebar is webapp-only, there is no `Sidebar` in `uilibs`, and every item links to a scaffold page (title and summary set, no content yet; Settings opens `/admin/settings`, whose eight sub-pages are listed in `routes/admin/settings/-nav.ts` and shown as an aside beside the page, or as a `Select` above it below the compact breakpoint, `settings/-settings-nav.tsx`), and it collapses to an icon rail (local state, not persisted; collapsed items keep their label as `aria-label` and a tooltip, and the expand trigger replaces the logo on hover or focus; a placeholder notification bell with a fixed unread count (`unread` in `-sidebar.tsx`, shown as a dot) sits at the end of the account strip beside the menu trigger, and above the avatar when collapsed); below the compact breakpoint it is hidden and `-topbar.tsx` (menu trigger, brand, notification placeholder) takes over), and `autoCodeSplitting` in `tsr.config.json` splits each route's component into its own chunk (the dashboard sample is one 8 kB chunk, loaded on navigation)); `.oxlintrc.json` switches off the React-compiler and a11y rules for `packages/uilibs/**`. `e2e` is a Playwright suite (`playwright.config.ts`; screen objects in `screens/<area>/*.screen.ts` with specs beside them, registered as fixtures in `fixtures/test.ts`, routes in `utils/routes.ts`); unless `E2E_BASE_URL` is set it builds the SPA and starts the Rust server alone on `127.0.0.1:3000` (it serves the built SPA from disk), and writes reports to `.output/`.                                                                                                                                                                                                                                          |

## Toolchain

- Rust `1.100.0` (`rust-toolchain.toml:13`), edition 2024 (`Cargo.toml:14`), workspace resolver 2.
- Formatting: `rustfmt.toml` (edition 2024, `max_width = 120`). A Claude Code `PostToolUse` hook (`.claude/hooks/format.sh`) formats every edited file inside the repository: `.rs` with `rustfmt`, `.md` with `rumdl fmt` (default rules, no line wrapping), and `.ts`/`.tsx`/`.js`/`.jsx`/`.json`/`.css` under `packages/` with the workspace-root `oxfmt`. Frontend style lives in `.oxfmtrc.json` (2 spaces, single quotes, no semicolons, sorted imports) and lint rules in `.oxlintrc.json` (type-aware through `tsrs-lint`, which oxlint picks up from the installed `tsrs`); both are installed at the pnpm workspace root. It needs `jq`; a missing formatter is skipped silently.
- Workspace lints (`Cargo.toml:17-20`): `missing_docs = "warn"`, `unreachable_pub = "deny"`, `private_interfaces = "deny"`. Each crate opts in with `[lints] workspace = true`.
- Build flags (`.cargo/config.toml`): `target-cpu=native`; `lld` on the musl and aarch64-gnu targets.
- Frontend: pnpm `12.21.0` (`package.json`).
- Developer tools: `just`, `cargo-nextest`, `rumdl`, `hurl`; optional: `cargo-hack` (feature combinations), `cargo-deny`, `sqlx-cli`. Check that a tool is installed before relying on it; do not install one unasked.

## Commands

Run every gate through `just` (`justfile` imports `scripts/task-*.just`; `just` alone lists the recipes).

| Gate                 | Recipe                              | Runs                                                                                                             |
| -------------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Format               | `just format` / `just format-check` | `cargo fmt --all` + `rumdl fmt .` + `pnpm format` (oxfmt on `packages/`; `--check` for all three; config in `.rumdl.toml`, `.oxfmtrc.json`)                                  |
| Check                | `just check`                        | `cargo check --workspace --all-targets`                                                                          |
| Typecheck            | `just typecheck`                    | `pnpm -r typecheck`: `tsrs --noEmit --fast` in every `packages/*` (`webapp` generates the route tree first); not part of `verify` |
| Lint                 | `just lint`                         | `cargo clippy --workspace --all-targets -- -D warnings` + `pnpm lint` (oxlint on `packages/`)                                                          |
| Test                 | `just test`                         | `cargo nextest run --workspace` (falls back to `cargo test --workspace`); E2E has its own `e2e-*` group (below)                                         |
| All of the above     | `just verify`                       | format-check, check, lint, test                                                                                  |
| API specs            | `just test-api [url]`               | `hurl --test` over `api/specs/**/*.hurl`, `base_url` defaults to `http://127.0.0.1:3000`; needs a running server |
| Feature combinations | —                                   | `cargo hack check --each-feature -p rusttp-server`, only when `cargo-hack` is installed                          |

Other recipes: `dev` (builds the email templates, then `pnpm --filter webapp dev`: the server on `http://127.0.0.1:3000` with Vite HMR behind it; one Ctrl-C stops both), `run <command>` (any app CLI command, e.g. `just run serve --bind 0.0.0.0:3000`), `build` (the email templates into `apps/server/emails`, the SPA into `apps/server/frontend`, then the release binary that embeds it, then prints its size) and `start` (runs `serve` from the release build), `deps`, and the `compose-*` (up, down, restart, exec, cleanup) / `docker-*` (build, images, run, shell into a `debug-nonroot` build, push) container tasks (`container/compose.yaml`, `deploy/Dockerfile`). Utility: `cleanup [--all] [--dry-run]` (removes every regenerable artifact: `target`, `apps/server/frontend` and `emails`, the route tree, Vite and email caches, Playwright reports; `--all` adds `node_modules`; prints each path and the space freed). Email (group `email` in `scripts/task-development.just`, `packages/emails`): `email-dev` (preview on `:3030`), `email-build [--verbose]` (writes `apps/server/emails/`; prints one `[emails]` summary line, each template with `--verbose`, and every failure), `email-check <name> [args]` (client compatibility of `templates/<name>.tsx`, e.g. `--use-preview-props`). Storybook (group `storybook` in `scripts/task-development.just`, `packages/uilibs`): `storybook` (dev server on `:6006`), `storybook-build` (into `packages/uilibs/.output/storybook`), `storybook-start` (`vite preview` of that build on `:6006`). E2E (`scripts/task-e2e.just`, Playwright in `packages/e2e`): `e2e-test [args]` (headless, all projects; e.g. `--project Chromium`), `e2e-chrome` / `e2e-firefox` / `e2e-safari` / `e2e-mobile` (headed, one project), `e2e-ui`, `e2e-report`, `e2e-install` (browsers, once).
