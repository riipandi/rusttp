# UI Components Index

updated: 2026-11-22T15:16:00+07:00

The inventory of `packages/uilibs/src`: what each component is, where it imports from, and what it is built on. Check it before writing a new component; extend an existing one when it already covers the need. `packages/webapp` consumes it (`uilibs` dependency, StyleX plugin in its Vite config, `UIProvider` and `ThemeProvider` at the root; see `frontend.md`).

## How to use and extend

- **Import path.** `uilibs/<path under src>`, resolved by the package `exports` map (`./src/*`, `./src/*/index.ts`, `./src/*.ts`, `./src/*.tsx`): `uilibs/base/button`, `uilibs/extra/card`, `uilibs/styles/tokens.stylex`, `uilibs/theme`. Inside the package, use the `#/*` alias (`src/*`) or a relative path.
- **Anatomy.** One folder per component, `<name>/{<name>.component.tsx, <name>.stylex.ts, <name>.stories.tsx, index.ts}`; `index.ts` re-exports the component and its styles. Exceptions: `base/provider.tsx` (one file), `extra/input-password` (no styles file), `extra/data-grid` and `extra/sortable`/`extra/kanban` (larger modules), `charts/` (primitives plus one story per chart type), `icons/` (one file per brand).
- **Styling.** StyleX only. Colors, spacing, type, radius, motion, and z-index come from `src/styles/` (`colors.stylex.ts`, `tokens.stylex.ts`, `popup.stylex.ts`, `utils.stylex.ts`, `themes.ts`), never from literals or non-StyleX imports. A component accepts `style` (StyleX styles) and merges it last in `stylex.props(...)`; it never takes `className` or a raw `style` object. Authoring rules: `stylex-authoring.md`; build setup: `stylex-installation.md`.
- **Text-entry `variant`.** Input, Textarea, SelectTrigger, Combobox (input, trigger, chips), AutocompleteInput, NumberField, InputGroup, InputPassword, InputPhone, and OTPField take `variant` `outline` (default, the bordered box), `faded` (neutral fill, no edge), `ghost` (transparent until hover), or `headless` (no box). `faded`, `ghost`, and `headless` keep the focus ring and the critical edge when invalid but have no 3:1 edge at rest, so give them a visible label (`controlVariants` in `styles/control.stylex.ts`).
- **Controls.** Every form control takes `size` (`sm` 32, `md` 36 default, `lg` 40; `xs` 28 on Button, Toggle, and Tabs) so a row of mixed controls shares one height; `size` sits on the part that is the box (`Input`, `SelectTrigger`, `ComboboxInput`/`ComboboxTrigger`/`ComboboxChips`, `AutocompleteInput`, `Textarea`) or on the root that holds the parts (`NumberField`, `OTPField`, `InputGroup`, `InputPassword`, `InputPhone`, `TabsList`, `Menubar`). A text control fills its container. Textarea, FileUpload, and Slider are Field controls like the rest. Built-in strings are one `labels` object per component with English defaults (never `text`, `label`, or `title` props); wrappers take `ref` as a prop. The recipes are in `stylex-authoring.md` ("Controls").
- **Primitives.** Base UI (`@base-ui/react`) for behaviour and accessibility; a component's header comment links the Base UI page and shows its anatomy. TanStack Table v9 and `@tanstack/react-virtual` (data grid), `@tanstack/charts` (charts), `react-day-picker` (calendar), `react-phone-number-input` (phone input), `react-resizable-panels` (resizable), `@dnd-kit/*` (kanban, sortable).
- **Stories.** Every component has `*.stories.tsx` beside it; `just storybook` serves them. Stories are grouped by prop axis and draw each axis with `Axis` (`src/contracts/story-axes.tsx`); the convention is `frontend.md` ("UI library"). Sample data follows `rules.md` ("Sample data"); the library's contracts are `frontend.md` ("UI library").
- **Theme.** `uilibs/theme` (`ThemeProvider`, `useTheme`, `ThemeSwitcher` (a ghost `Button`; `labels`: `toDark`, `toSystem`, `toLight`), `ThemeScript` from `uilibs/theme/theme-script` to set the theme before first paint); `data-theme` on the root carries `light`/`dark`. `UIProvider` (`base/provider`) sets CSP nonce and text direction for Base UI and goes at the app root.

## Choosing between look-alikes

- **Sheet or Drawer.** Sheet is a Dialog that slides in from an edge (a navigation panel, a settings panel); Drawer is a swipe panel with snap points (a touch-first sheet).
- **Dialog or Alert Dialog.** Dialog is content the user may dismiss; Alert Dialog needs an answer (a destructive or high-risk confirmation, `color='critical'` on the action).
- **Select, Combobox, Autocomplete, or Command.** Select picks one value from a short fixed list; Combobox picks from a list the user searches (and `ComboboxChips` takes several); Autocomplete suggests free text that may match no item; Command is a palette of actions, rendered inline.
- **Tooltip, Popover, or Preview Card.** Tooltip names a control (no interactive content); Popover holds interactive content; Preview Card previews a link on hover.

## 3. Charts, icons, and foundations

- **Charts (`uilibs/charts`).** shadcn-style primitives on TanStack Charts: `ChartContainer` (takes `config`), `Chart` (takes a `defineChart()` definition, `ariaLabel`, `height`), `ChartLegend`, `useChartConfig`. A series key in `config` matches a mark `id`. A mark color is any CSS color, a theme token included: TanStack paints it as an SVG attribute and the browser resolves `var()` there (checked in Chromium, light and dark), so a series follows the theme. A series that carries meaning needs 3:1 against the page or a second cue (a label, a pattern, a legend entry); `seriesColors` (`charts/chart.samples.tsx`) and the host's default palette use the `foreground*` tokens (5.6:1 or better on the page in both themes); a `background*` fill as a series color falls short (warning 1.86:1 and neutral 1.30:1 in light), so label it. Give each chart in a document an explicit `idPrefix`. `charts/stories/` holds one recipe per chart type: area, bar, bar list, Bollinger band, boxplot, category bar, combo, cumulative histogram, donut, dumbbell, heatmap, line, lollipop, progress circle, scatter plot, slopegraph, spark chart, tracker; `chart.samples.tsx` is story data, not public.
- **Brand icons (`uilibs/icons`).** `FacebookIcon`, `GitHubIcon`, `GoogleIcon`, `InstagramIcon`, `LinkedInIcon`, `TelegramIcon`, `ViteIcon`, `WhatsAppIcon`, `XIcon`. General-purpose icons come from `@keyline-icons/react`, wrapped by `Icon` for sizing.
- **Styles (`uilibs/styles/*`).** `control.stylex` (`ControlSize`, `DenseControlSize`, `controlSizes`, `controlBase`, `controlPress`), `colors.stylex` (color and `shadow` variables, with `borderControl` for control edges; `backgroundDisabled*`, `backgroundElevationRaised`, and the `*-intense` shadows were removed; the primary and `brand` ramp is the logo's orange, hue 39.4 in light and 45.84 for dark foregrounds and borders, kept at 4.5:1 or better against `onBackgroundPrimary` for WCAG AA), `tokens.stylex` (fonts, `fontSize`, `unit`, `stroke`, `container`, `radius`, `zIndex`, `viewport`, `breakpoints`, `duration`, `easing`), `popup.stylex` (`popupFx`), `utils.stylex` (`ring`, the box-shadow edge for popups; use it instead of a border on popups; `visuallyHidden`, text for assistive technology only; `focusRing.root`, the keyboard focus outline, composed first), `themes` (dark theme class).
- **Hooks (`uilibs/hooks/use-media-query`).** `useMediaQuery`, `useIsMobile`.
- **Assets (`uilibs/assets/*.css`).** `reset.css` (layer `reset`), `fontface.css`, `globals.css`; the StyleX plugin pins its layers after `reset` (`packages/plugins/src/stylex.ts`).
