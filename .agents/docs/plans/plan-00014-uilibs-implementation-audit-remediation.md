## Objective

The report `uilibs implementation audit: Base UI, StyleX, tests, Storybook, Vite` (commit `05ccbe1`, 81 findings: 3 high, 24 medium, 54 low; merged into 26 recommendations) found no security flaw and no reopened decision, but it found a story-wait rule that is written and not enforced, a data grid whose drag styles drop its geometry, a double-firing `FileUpload`, an untested data grid write path, and a dev-time StyleX race. This plan does every recommendation (P0, P1, P2) and every finding: each of the 81 IDs maps to a phase or to a "not doing, because" line in the finding map. After it, the 10 s wait is configuration and not a convention, the data grid's write path is tested on a real TanStack table, the popup wrappers share one shell, the StyleX sheet is minified, CI keeps its failure evidence, and the dead code the audit listed is gone. It adds no UI feature and changes no token value except the removal in phase 47. It does not push.

## Execution rules

- **Nothing runs before the owner's go-ahead**, and then phase by phase. The go-ahead for a phase authorizes its one commit with the message in its heading and nothing else. After the last phase the coordinator stops and recommends the closing state; it does not push.
- **Branch.** The owner has not asked for one: cut `fix/uilibs-audit-remediation` from `main` at `05ccbe1` unless told to work on `main`. Never push, rewrite history, `stash`, `reset`, `checkout .`, `clean`, or `--no-verify`.

For waves 1 to 3 it starts one thread per track with `create_thread` on the local runner (`executor: runner`, `working_directory` this checkout, no `worktree`, never an orb): at most 4 at once (wave 1: 3, wave 2: 4, wave 3: 2). - **Commit protocol in a shared tree (every thread, every phase):** record `git status --porcelain` before the first edit (files already modified belong to someone else); edit only the phase's paths; format and lint only those paths (`pnpm exec oxfmt --write <paths>`, `pnpm exec oxlint <paths>`, never `pnpm format`); stage explicit paths and commit with `git commit -m "<message>" -- <paths>`; if `.git/index.lock` exists wait 5 seconds and retry for up to a minute, never delete it; `git show --stat HEAD` must list only the phase's paths.
- **Shared-tree hazards.** Typecheck is whole-package: an error in a file another track owns is that track's work in progress, so wait and rerun. A scoped run is `pnpm --filter uilibs exec vitest run --project storybook --project storybook-dark <paths>` (and `--project unit <path>`). During a wave, tracks run Chromium only and scoped; Firefox, WebKit, the full suite, and `storybook:build` run at the wave's docs phase, when no track is active. Never run Storybook and a test run at the same moment until phase 9 lands and phase 16 re-tests the advice.
- **Experiments are reverted.** A scratch edit (a mutation check, a probe story, a scratch compile) is copied aside first and restored byte for byte, scratch files live under `/tmp`, and `git status` must be clean of them before the commit.
- **A UI-visible change is also inspected:** light and dark screenshots of the affected state, viewed. Sample data is Dan Brown and Harry Potter. No dependency beyond the ones D8, D10, D11, and D15 name.
- **Per-phase validation runs before the phase's commit;** the "Gate" in each phase means the scoped story and unit runs plus typecheck, lint, and format on the phase's paths.
