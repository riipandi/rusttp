# Fix the 15 data grid audit findings — one parallel cleanup wave, then serial accessibility work

## Objective

`audit-00003-uilibs-data-grid.md` (report only, plan 00011 phase 56) found 15 problems in `packages/uilibs/src/data-grid`: two medium (no keyboard path to resize a column, none to activate an `onRowClick` row), twelve low, and one info, all open, plus two open questions (row labels as functions of the row, and a table-name prop). After this plan, a grid has an accessible name, every control names its row or column, loading and drags are announced, the two medium gaps have a keyboard path built on WAI-ARIA patterns, the stylesheets use tokens, and the pure logic has unit tests. The plan does not touch the webapp (it has no grid) and does not push.

The decisions that are not settled by the code are the 36 questions of the [data grid audit questionnaire](https://ampcode.com/artifacts/data-grid-audit-questionnaire-9990e235-2e6f-43a9-bb19-a9a5c4f90e83) (Q00 to Q35). A phase builds the recommended answer unless the owner answered differently (Q00); each phase names its questions.

## Decisions

- **D1 (2026-11-25): all 15 findings are in scope; the questionnaire sets scope and design.** A "defer" answer moves the finding to `issue-00009` (Q04) and drops its phase; a "won't fix" answer records the reason in the audit and in `architecture.md`; both are noted on the phase. An unanswered question takes its recommendation (Q00). Rejected: a plan for the two medium findings only — the owner asked for all 15, and the low ones touch the same files.
- **D2 (2026-11-25): no backward compatibility.** Label shapes and props change in place (`selectRow` and its four siblings become functions of a name; `DataGridTable` requires a name). The webapp has no grid, so typecheck finds every caller inside `packages/uilibs`. Rejected: keeping string labels beside function labels — an alias for a screen the owner has no consumer on.
- **D3 (2026-11-25): two waves, because the file sets decide it.** Wave 1 (phases 1 to 7) is three parallel tracks with disjoint file sets and no edit to `data-grid.mdx` or `data-grid-labels.tsx`. Wave 2 (phases 8 to 16) is serial: every phase edits `data-grid-labels.tsx`, `data-grid.mdx`, and a story file, and phases 8, 9, 15, and 16 share `data-grid-column.tsx`, `data-grid-table-head.tsx`, and `data-grid-table-body.tsx`. Rejected: parallel accessibility phases — two threads would stage each other's half-done hunks of one mdx page. Rejected: worktrees and orbs — the owner ruled them out; this is one checkout.
- **D4 (2026-11-25): cleanup runs before the new interaction styles (Q03).** Phases 15 and 16 add focus styles to the same two stylesheets that phases 1 and 2 clean, so wave 1 goes first; the two waves never run at the same time.
- **D5 (2026-11-25): an unverified finding is reproduced before it is fixed.** F-06, F-07, and F-09 start with a play that fails on the current code. A finding that does not reproduce closes as `false_positive` in the audit with the evidence; the play stays only if it guards behavior that can regress. A failing play is never committed on its own (`frontend.md`).
- **D6 (2026-11-25): keys follow the WAI-ARIA Authoring Practices.** Resize is the window splitter pattern (a focusable `separator` with value attributes, Q20); row activation is the grid pattern's row-focus form with one Tab stop (Q22). Rejected: a custom key scheme — consumers and screen reader users already know these.
- **D7 (2026-11-25): new strings are flat `DataGridLabels` entries.** Functions where a name or count is interpolated, English defaults, `labels` and never `i18n`, spelled-out size names, `getRowLabel` named after Kanban's name-by-function pattern (`frontend.md`, "UI library").
- **D8 (2026-11-25): committed tests only where they guard behavior.** Unit tests for pure logic (clipboard, fill, table utilities, the resize step function) with expected values written out by hand; plays for interaction. A new play is mutation-checked once: it fails on the old code, then the scratch edit is reverted and not committed.

## Execution rules

- **Nothing runs before the owner's go-ahead.** Pacing follows Q01 (by default the run stops after each wave). Each phase's heading names its suggested commit message; the go-ahead authorizes those commits and nothing else. After the last phase, the coordinator stops and recommends the closing state; it does not push.
- **Branch.** `fix/data-grid-audit`, cut from `main` at `97c3245` (fast-forwarded to `origin/main` after PR #3). Never push, rewrite history, `stash`, `reset`, `checkout .`, `clean`, or `--no-verify`.
- **Threads (Q02).** The thread the owner names is the **coordinator**; it runs every wave 2 and wave 3 phase itself. For wave 1 it starts one thread per track with `create_thread` on the local runner (`executor: runner`, `working_directory` set to this checkout, no `worktree`, never an orb), at most 3 at once. Each track thread runs only its phases, in order, and reports each commit hash to the coordinator with `send_thread_message`. With Q02 B, one thread runs the phases in numeric order.
- **Only the coordinator edits this plan, `index.md`, `audit-00003`, and the shared docs.** Wave 2 and 3 phases record their status and note, and flip their audit row, in the same commit as the phase. Wave 1 tracks report instead; the coordinator records all of wave 1 in one `docs(plans): record wave 1 of plan 00012` commit at wave close (a ledger commit, not a phase).
- **Commit protocol in a shared tree (every thread, every phase):** (1) record `git status --porcelain` before the first edit; files already modified belong to someone else. (2) Edit only the phase's file set (the ownership table). (3) Format and lint only your paths: `pnpm exec oxfmt --write <paths>`, `pnpm exec oxlint <paths>`; never `pnpm format`. (4) Stage explicit paths and commit with `git commit -m "<message>" -- <paths>`. (5) If `.git/index.lock` exists, wait 5 seconds and retry for up to a minute; never delete it. (6) `git show --stat HEAD` must list only the phase's paths; otherwise stop and report, never amend another thread's commit.
- **Shared-tree hazards.** Typecheck is whole-package: an error in a file you do not own is another track's work in progress; wait and rerun. A scoped run is `pnpm --filter uilibs exec vitest run --project storybook --project storybook-dark src/data-grid` (and `--project unit <path>` for unit tests). A thread never runs Storybook and a test at the same moment, and never runs `storybook:build` (the coordinator builds at wave close). The coordinator runs the full gate only when no track thread is active.
- **Per-phase validation runs before the phase's commit** and includes `just typecheck`, lint and format on the phase's paths, and `just check-ui-docs` for any phase that touches `data-grid.mdx` or a Playground. A UI change is also inspected: light and dark screenshots of the affected state, viewed, before and after where the look changes.
- **Sample data:** Dan Brown and Harry Potter only (`rules.md`). **No new dependency.** If a phase meets a choice the questionnaire does not settle, it stops and asks in the `AGENTS.md` shape.
