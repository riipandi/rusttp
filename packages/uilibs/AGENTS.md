# packages/uilibs

The shared React component library: StyleX styles over Base UI, compiled from source by each consumer. Rules: `.agents/docs/frontend.md` ("UI library"); catalog: `.storybook/stories/components.mdx`; styles: `.agents/docs/stylex-authoring.md` (and `stylex-installation.md` only for the compiler pipeline).

- Before building or changing any UI, read the catalog `.storybook/stories/components.mdx` and the component's `<name>.mdx`; reuse a component from it before writing one. A new, renamed, or removed component updates the catalog in the same change.
- StyleX only: every color, size, and motion value comes from `src/styles/` tokens; no `className` or raw `style` beside `stylex.props`; conditions nest in the value, never as top-level keys. Tokens change only on the owner's decision.
- A control takes `size` and composes `controlBase` or `controlPress` (`stylex-authoring.md`, "Controls"); built-in strings are one `labels` prop with English defaults; `uilibs` imports no i18n.
- Controls show only in `Playground` (`.storybook/preview.tsx` turns them off); its `include` list names them and its `render` reads the args (`frontend.md`, "UI library").
- Stories are grouped by prop axis (`Playground`, `Variants`, `Sizes`, `States`, behavior stories apart) with `Axis` from `src/contracts/story-axes.tsx` and the `play` helpers in `src/contracts/control-sizes.tsx`; no `minWidth` decorator and no `layout: 'centered'` (`frontend.md`, "UI library").
- Every component folder has a docs page, `<name>.mdx` (not `.stories.mdx`), beside its stories: import, anatomy, examples (`Canvas` of its stories, each with a `docs.source.code` snippet), an `## Accessibility` section for a component with keys or a naming rule (`Key | Action` table, proved by its `Keyboard` story; every overlay also has an `Open` story), then the API reference with props, data attributes, and caveats; a prop, part, or attribute change updates it in the same commit (`frontend.md`, "UI library"). `styling.mdx` and `theming.mdx` in `.storybook/stories/` cover `style`, atoms, and the theme.
- A part's props are `PartProps<typeof Base.Part>` (never a hand-written `Omit<…, 'className' | 'style'>` or `style?: StyleXStyles`; `src/styles/style-prop.test.ts` guards it); a story queries portaled parts with `screen`, not `within(document.body)`; imports inside the package are relative (`#/` is banned).
- Every component has a story; the story passes the a11y gate (`pnpm --filter uilibs test`, axe in light and dark). Waits are 10 s by configuration (`.storybook/preview.tsx`, `src/contracts/overlay.ts`): a story never sleeps and never writes a `timeout: 10000` (`frontend.md`, the gate and play rules). A Storybook dev server may run beside the test run.
- Every story renders at 390 px and fails if its page is wider; a story that scrolls inside its own box on purpose sets `parameters: { overflow: 'allowed' }`, one that needs room sets `globals: { viewport: { value: 'desktop', isRotated: false } }` (an object, never a string: the test addon reads `.value`) (`frontend.md`, "Overflow gate").
- `just check-ui-docs` diffs each `<name>.mdx` props table and each `Playground` `include` against the code (`scripts/check-docs.ts`); a prop, control, or doc row you add or remove keeps it clean. `pnpm --filter uilibs rebrand <hue>` moves the primary palette (`stylex-authoring.md`, "Tokens and shared recipes").
- A data grid table is always named (`aria-label` or `aria-labelledby`, required by type) and its row controls are named after their row (`getRowLabel`); keyboard behavior of rows and resize separators is listed in `data-grid.mdx` and proved by the `Row click`, `Column resizing, keyboard`, and `Focus` stories (a grid is never focused without a visible ring, and the resize direction follows `dir`, not the table option); a row's or cell's geometry is a dynamic style in the same `stylex.props` call, never a raw `style` beside it (`frontend.md`, "UI library").
- `base` never imports from `extra` (except Button's `Spinner`).
