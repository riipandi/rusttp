# ThemeScope

Draws one part of the page in its own color mode: a dark sidebar on a light page, or a light card on a dark one.

## Import

```jsx
import { ThemeScope, usePortalContainer } from 'uilibs/theme'
```

Built on Base UI [useRender](https://base-ui.com/react/utils/use-render), so `render` swaps the `div` for another element. Props not listed here pass through.

## Anatomy

- **ThemeScope:** the subtree's root, a `div` by default. It applies the theme class for its mode, paints the page surface and text color, and sets `color-scheme`, so native scrollbars and form widgets match.
- **A portal element:** a second, empty `div` at the end of the body with the same theme class. It exists only for popups opened from inside the scope.

```jsx
<ThemeScope colorMode='dark'>{content}</ThemeScope>
```

### Popups

A popover, menu, select, tooltip, dialog, or toast opened from inside a scope portals out of it. It opens into the scope's portal element, so it keeps the scope's mode. Without that, it would open in the page's mode, a light popup over a dark panel.

## API reference

`ThemeScope` also takes `style`: StyleX styles that replace `className` and `style`. See [Styling](?path=/docs/styling--docs).

### ThemeScope

| Prop        | Description                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `colorMode` | `dark`, `light`, `inverted` <br /> The scope's mode. `inverted` flips the enclosing scope, or the page's theme outside one. Required. |
| `render`    | `ReactElement`, function <br /> Swaps the `div` for another element, such as a `section` or an `aside`.                               |

| Data attribute    | Description                                                                    |
| ----------------- | ------------------------------------------------------------------------------ |
| `data-color-mode` | Set by this library to the resolved mode, `dark` or `light`, never `inverted`. |

### usePortalContainer

`usePortalContainer()` returns the element a popup opened from here should portal into: the nearest scope's portal element, `null` while it mounts, or `undefined` outside any scope. Pass it as the `container` of a Base UI `Portal`. Every popup in this library already does; use it only for a popup you build on Base UI yourself.

## Caveats

- The page's own theme still comes from `ThemeProvider`. A scope only overrides the tokens below it, so it needs no provider of its own; without one, `inverted` treats the page as light.
- A popup opened from inside a scope renders in the scope's portal element, not in the body, so a CSS rule that targets `body > *` reaches the element but not the popup.
- The portal element is created after the first render. A popup opened before it exists waits a frame.
- The body font is not part of the theme (`fontFamily.body` is set in `globals.css`), so a scope inherits it from the page.
