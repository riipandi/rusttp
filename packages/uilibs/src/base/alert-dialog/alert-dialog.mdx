# Alert Dialog

A modal dialog that needs an answer before the user continues, for destructive or high-risk confirmations. Use Dialog for content the user may dismiss.

## Import

```jsx
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogMedia,
  AlertDialogOverlay,
  AlertDialogTitle,
  AlertDialogTrigger
} from 'uilibs/base/alert-dialog'
```

Built on Base UI [Alert Dialog](https://base-ui.com/react/components/alert-dialog). Props not listed here pass through.

## Anatomy

- **AlertDialog:** the root. It holds the open state.
- **AlertDialogTrigger:** the button that opens the dialog.
- **AlertDialogContent:** the popup. It renders the portal and the overlay itself, and has no close button.
- **AlertDialogHeader:** groups the media, title, and description.
- **AlertDialogMedia:** an icon tile above the title. Optional.
- **AlertDialogTitle:** the dialog's name.
- **AlertDialogDescription:** what the user is confirming.
- **AlertDialogFooter:** holds the buttons.
- **AlertDialogCancel:** a button that closes the dialog.
- **AlertDialogAction:** the confirming button. It also closes the dialog.
- **AlertDialogOverlay:** exported only for custom compositions. `AlertDialogContent` already includes it.

```jsx
<AlertDialog>
  <AlertDialogTrigger />
  <AlertDialogContent>
    <AlertDialogHeader>
      <AlertDialogMedia />
      <AlertDialogTitle />
      <AlertDialogDescription />
    </AlertDialogHeader>
    <AlertDialogFooter>
      <AlertDialogCancel />
      <AlertDialogAction />
    </AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>
```

## Accessibility

The popup is an `alertdialog` named by `AlertDialogTitle` and described by `AlertDialogDescription`. Always render both: without a title the dialog has no name. While it is open, the page behind it is inert, Tab stays inside the popup, and Escape closes it. The `Keyboard` story walks this path, and the `Open` story keeps the popup open so the accessibility check reads it.

| Key                     | Action                                                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `Enter` or `Space`      | On `AlertDialogTrigger`: opens the dialog. On `AlertDialogCancel` or `AlertDialogAction`: presses it. |
| `Tab` and `Shift + Tab` | Moves focus between the buttons inside the popup. It wraps and never leaves the popup.                |
| `Escape`                | Closes the dialog and returns focus to the trigger.                                                   |

- Focus moves to the first button in the popup, in document order: put `AlertDialogCancel` before `AlertDialogAction` so the safe answer is the one focused. Pass `initialFocus` to `AlertDialogContent` to pick another control.
- There is no built-in close button, so the dialog is closed by `AlertDialogCancel`, `AlertDialogAction`, or Escape. Both buttons need visible text or an `aria-label`.
- Keyboard behavior is Base UI's; see the Base UI [Alert Dialog](https://base-ui.com/react/components/alert-dialog) page for focus options such as `initialFocus` and `finalFocus`.

## API reference

Every part except `AlertDialog` and `AlertDialogTrigger` also takes `style`: StyleX styles that replace `className` and `style`. See [Styling](?path=/docs/styling--docs). On `AlertDialogContent` it styles the popup; on `AlertDialogAction` and `AlertDialogCancel` it styles the button.

### AlertDialogTrigger

| Data attribute    | Description                           |
| ----------------- | ------------------------------------- |
| `data-popup-open` | Present while the dialog is open.     |
| `data-disabled`   | Present when the trigger is disabled. |

### AlertDialogOverlay

| ---------------- | --------------------------------------------------------------------- |
| `blurredOverlay` | `boolean` <br /> Blurs the page behind the backdrop. Default `false`. |

| Data attribute        | Description                           |
| --------------------- | ------------------------------------- |
| `data-open`           | Present while the dialog is open.     |
| `data-closed`         | Present while the dialog is closed.   |
| `data-starting-style` | Present as the dialog begins to open. |
| `data-ending-style`   | Present as the dialog closes.         |

| Prop             | Description                                                           |
| ---------------- | --------------------------------------------------------------------- |
| `size`           | `small`, `medium` <br /> The width of the dialog. Default `medium`.   |
| `blurredOverlay` | `boolean` <br /> Blurs the page behind the backdrop. Default `false`. |

| Data attribute            | Description                                       |
| ------------------------- | ------------------------------------------------- |
| `data-open`               | Present while the dialog is open.                 |
| `data-closed`             | Present while the dialog is closed.               |
| `data-starting-style`     | Present as the dialog begins to open.             |
| `data-ending-style`       | Present as the dialog closes.                     |

| Prop      | Description                                                                                                                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

## Caveats

- `AlertDialogAction` and `AlertDialogCancel` both close the dialog. To keep it open while work runs, call `event.preventBaseUIHandler()` in the action's `onClick` and close through the dialog's `open` state later.
- `AlertDialogContent` already wraps itself in a portal with an overlay. Do not wrap it in a portal.
- A dialog taller than the window scrolls as a whole with its backdrop, so its title and actions can always be reached.
- `medium` is wider than `small` only at 660px and up. Below that both sizes have the same width.
